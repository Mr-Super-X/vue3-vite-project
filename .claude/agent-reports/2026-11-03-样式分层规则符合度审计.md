## 一、总体结论

**骨架层近乎满分，消费层局部失控，暗色主题存在三处「文档声称 ≠ 代码实现」的实质性漂移。**

- 六条规则中 **4 条符合或等价符合**（目录骨架 / tools 无产出 / utilities / 组件 BEM 约定）
- **z-index 治理满分**：全仓 >100 硬编码 0 违规；既有审计发现 #3（portal 撞值）已修复，`portal-tokens.scss:13` 现为 `var(--z-index-fixed)` 引用

- **暗色主题三条漂移链**（本次审计最重要发现，详见发现 #1/#2/#3）：

  3. `injectBrandColor` 注释承诺「改品牌色含 EP 组件全局生效」，实际只 `setProperty('--color-primary')`，EP 变量为编译期字面量、运行时不受其控

## 五、合规亮点（本次核实确认）

1. **z-index 治理全仓 0 违规**：13 级语义 token + 「局部 1-100 自管」成文约定被全仓遵守，普查 >100 硬编码零命中
2. **additionalData 注入绝对安全**：单行 `@use 'bem' as * with(...)`，bem.scss 纯 mixin 零产出——经典重复打包坑不存在
3. **admin 布局级暗色方案是 monorepo 正确解法**：`[data-theme='dark'][data-layout='default']` 双属性选择器 + mixin 施加，多布局并存互不污染，可作为其他端补齐暗色时的范本
4. **AppMenu teleport 弹层局部变量模式合理**：teleport 逃逸出布局容器后的 EP 变量局部重定义（含暗色覆盖），是 teleport 与 CSS 变量作用域矛盾的标准解法
5. **既有审计行动项在收敛**：portal z-index 撞值已修复（发现 #3 闭环）
