## 一、总体结论

**项目样式架构成熟度高于规范文本要求，无需推倒重构；主要工作是「规范追认现状 + 两处语义对齐」。**

- 五层结构全部有物理承载（monorepo 映射：L1/L2/L3 全局层在 `packages/ui/src/assets/styles/`，端级 tokens 在各 app layouts/modules，L5 在 SFC）
- 用户最强调的两条纪律执行度 **~100%**：全仓 191 个 `<style>` 块 **scoped = 0**（其中 3 块为 `<style module>` 有意识例外，见发现 #9）；BEM 双轨（运行时 `createNamespace` + 编译期 SCSS mixin）覆盖全部有样式组件
- `!important` 真实声明仅 6 处（4 处 a11y 降级合法例外 + 2 处 docs 演示注释声明例外）
- 与规范的实质分歧只有两处：① tokens 与 EP 变量的「源/镜像」关系倒置；② 规范目录是单应用形态，项目是 monorepo 映射形态

## 三、合规亮点（值得写进规范的既有实践）

1. **EP 灯色阶算法级复刻**：`theme-vars.scss` 用 `color.mix($color, white, N%)` 生成 light-3/5/7/8/9，与 EP theme-chalk 内部算法逐一核对一致，主色变更时 25 个变量自动联动
2. **admin 布局级主题隔离方案**（`default-tokens.scss`）：EP 变量覆盖以 mixin 导出、由容器 `.vv-default-layout` 施加而非 `:root` 全局污染，teleport 弹层由 `[data-layout='default']` 属性选择器补——**多 app 各持品牌色（admin 紫 #5b5bd6 / portal 黑白 / big 科技蓝）的 monorepo 正确解法**，比规范「:root 方式 A」更适配本仓
3. **组件级覆盖带契约测试**：`xform-contract.spec.ts:73` 机械锁定 `XForm.vue` 必须 import 覆盖文件，防回归
4. **z-index 治理注释文化**：variables.scss:83-96 每级 token 带语义注释 + 2026-10-29 审计留痕；NetworkBanner 1999 带「低于 ElMessage 2000+」原因注释
5. **端级 tokens 前缀事实标准**：`--login-*`(16) / `--portal-*`(13) / `--h5-*`(4) / `--big-*`(8，含 rgb 分量形态供 rgba 组透明度)——各端语义隔离清晰

## 五、规范目录结构的 monorepo 映射（供修订规范时引用）

| 规范目录（单应用形态）          | 项目等价物（monorepo 形态）                                         |
| ------------------------------- | ------------------------------------------------------------------- |
| `src/styles/index.scss`         | `packages/ui/src/assets/styles/index.scss`（六段加载顺序头注完整）  |
| `styles/tokens/_variables.scss` | `variables.scss` + `theme.scss`（单文件承载，未拆 tokens/ 子目录）  |
| `styles/base/_reset.scss`       | `reset.css` + npm normalize.css（app-styles 三件套）                |
| `styles/element/_button.scss`   | `element-overwrite/`（全局变量级）+ 组件目录 `styles/`（组件级）    |
| `styles/layout/`                | 各 app `layouts/<l>/styles/*-tokens.scss`（布局级 tokens 就近布局） |
| `styles/themes/_dark.scss`      | `theme.scss` 内 light/dark mixin 集中（未拆文件，mixin 化更优）     |
| `styles/utilities/`             | `custom.scss`（`.vv-*`）+ UnoCSS `virtual:uno.css`                  |

**结论**：规范的每一层都有对应物理承载，目录形态差异是单应用→monorepo 的必然映射，不构成违规。
