# 模块化架构总览

> 涵盖项目 src/ 下**所有可复用模块**（directives / plugins / components / utils / store / router）的设计原则、目录结构、统一范式与扩展流程。
> 与各模块配套的详细规范（路由、主题、BEM、构建工具等）见 docs/01-07。

---

## 1. 设计原则

| 原则         | 说明                                                           |
| ------------ | -------------------------------------------------------------- |
| **单一职责** | 每个模块只做一件事（如 directives 只管自定义指令）             |
| **范式一致** | 同一类模块用同一套约定（如所有 directives 都 install 模式）    |
| **类型优先** | TypeScript strict + exactOptionalPropertyTypes 严格模式        |
| **单一来源** | 同类配置只在一处维护（如 alias 系统在 vite + tsconfig 双映射） |
| **可扩展**   | 预留扩展点（plugins.errorHandler.report 让用户接 Sentry）      |

---

## 2. 目录结构（src/）

```
src/
├── api/               # HTTP 接口层（axios 封装 + 各业务模块 API）
├── assets/            # 静态资源（styles / images / fonts）
├── components/        # 全局通用组件（仅放 common/，**不**放布局专用组件——布局组件归 layouts/<m>/components/）
│   ├── common/        # 通用组件（AsyncState / ErrorBoundary 等）
│   └── index.ts       # 自动注册插件入口（仅扫 common/）
├── composables/       # Vue 组合式函数（useXxx）
├── directives/        # 自定义 Vue 指令（v-xxx）
│   ├── _utils.ts       # 通用 debounce + isFunction
│   ├── *.d.ts         # 各指令类型定义
│   ├── *.ts           # 各指令实现
│   └── index.ts       # install 模式统一注册
├── enums/             # 枚举常量
├── layouts/           # 路由级布局（blank / default / portal）—— 每个 layout 自包含：
│                     #   ./components（私有子组件，如 default 的 Header/Sidebar）
│                     #   ./config（布局配置，如 portal/config/nav）
│                     #   ./images（布局资源）
│                     #   ./styles（布局专属样式变量，如 portal/styles/portal-tokens）
│                     # 禁止跨目录到 src/components/ 引用组件
├── locales/           # i18n 国际化
├── modules/           # 业务模块（自包含）
│   └── <feature>/     # 按需包含以下子目录（非强制 6 件套，有多少算多少）：
│       ├── routes/    # 路由配置（有页面时必有）
│       ├── views/     # 页面组件（有页面时必有）
│       ├── store/     # 模块私有 store（可选）
│       ├── apis/      # 模块私有接口（可选；跨模块共享接口放 src/api/modules/）
│       ├── components/# 模块私有组件（可选）
│       ├── config/    # 模块配置（可选，如 home/config）
│       ├── styles/    # 模块样式（可选，如 auth/styles）
│       └── index.ts   # 模块对外接口（模块间通信唯一通道）
├── plugins/           # Vue 插件（全局功能）
│   ├── *.d.ts         # 类型定义
│   ├── *.ts           # 插件实现
│   └── index.ts       # 统一注册入口
├── router/            # 路由核心（auto-register / guards / types）
├── store/             # Pinia 全局 store（跨模块共享）
│   ├── modules/       # 各个 store 模块（app / user / theme / dict / tags-view；router 通过按需 import 引入避免循环）
│   └── index.ts       # pinia 实例（默认导出 + 集中 re-export 5 个 store；router store 未 re-export）
├── types/             # 项目级 TypeScript 类型（env.d.ts / auto-imports / components）
├── utils/             # 通用工具函数（纯函数 + Vitest 单测）：
│                     # 工具：storage / dayjs / bem / format / validate / safeAsync / consoleBadge / autoImport / caseConvert
│                     # 聚合：index.ts + 各 .spec.ts 同级（详见 §3.4 范式）
└── components/
    ├── common/        # 通用组件（自动注册为 Vue 全局）
    │   ├── _internal/ # 内部工具（naming 等）
    │   └── ...        # AsyncState.vue / ErrorBoundary.vue / index.ts
    └── index.ts       # 自动注册插件入口
├── App.vue
└── main.ts            # 应用入口
```

**核心原则**：

- **每个子目录有独立边界**——可独立测试、独立维护
- **范式一致**——所有子目录的注册入口都是 `export default { install(app) {...} }`（如果有 install 行为）

## 3. 4 块公共范式

项目内有 4 类"可注册模块"，每类都有统一的范式约定：

### 3.1 Directives 范式

```ts
// xxx.d.ts — 类型定义
export type ElHTMLElement = HTMLElement
export interface XxxBinding { value: ...; arg?: string }

// xxx.ts — install 模式实现
import type { App } from 'vue'
import { isFunction } from './_utils'
import type { ElHTMLElement, XxxBinding } from './xxx.d'

export default {
  install(app: App) {
    app.directive<ElHTMLElement, XxxBinding['value']>('xxx', {
      mounted(el, binding) { ... }
    })
  }
}

// index.ts — 统一注册入口
import type { App } from 'vue'
import xxx from './xxx'

const install = (app: App) => app.use(xxx)
export default install
```

**约定**：

- 每个指令独立 `.d.ts` 类型文件
- install 模式导出
- 通用工具放 `_utils.ts`（前缀下划线）
- index.ts 统一注册

### 3.2 Plugins 范式

与 Directives 同形（install 模式 + .d.ts 分离 + index.ts 统一注册）：

```ts
// xxx.d.ts
export interface XxxOptions { ... }
export interface PluginsOptions { xxx?: XxxOptions | false }

// xxx.ts
import type { App } from 'vue'
import type { XxxOptions } from './xxx.d'

export default {
  install(app: App, options: XxxOptions = {}) { ... }
}

// index.ts
const install = (app: App, options: PluginsOptions = {}) => {
  if (options.xxx !== false) app.use(xxx, options.xxx)
}
export default install
```

### 3.3 Components 自动注册范式

```ts
// src/components/index.ts
import dayjs from 'dayjs' // 仅类型用

// eager 模式：构建时内联所有 common 下的 .vue
const modules = import.meta.glob<{ default: Component }>('./common/**/*.{vue,Vue}', { eager: true })

const install = (app: App) => {
  for (const [path, mod] of Object.entries(modules)) {
    if (isExcluded(path)) continue // _ 开头或 . 开头跳过
    const name = resolveComponentName(path, mod.default?.name)
    if (isDuplicate(name, registeredNames)) {
      warn
      continue
    }
    app.component(name, mod.default)
    registeredNames.add(name)
  }
}
export default install
```

**约定**：

- `common/` 下的 `.vue` 自动注册为全局组件
- `_` / `.` 开头的文件视为内部组件跳过
- 重复 name warn + 后注册覆盖

### 3.4 Utils 范式

```ts
// xxx.ts — 纯函数工具
export function xxxFn(input: Input): Output { ... }

// xxx.spec.ts — Vitest 单测
import { describe, it, expect } from 'vitest'
describe('xxxFn', () => {
  it('case', () => { expect(xxxFn(input)).toBe(expected) })
})
```

**约定**：

- 纯函数（无副作用）+ 完整类型签名
- 每个工具函数配 Vitest 单测
- 不依赖 Vue（与框架解耦）

## 4. Directives 模块详解

### 当前指令清单

| 指令               | 用法                                                                            | 行为                                                                                                |
| ------------------ | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `v-inputDebounce`  | `v-inputDebounce:300="onInput"`                                                 | input 事件 trailing edge 防抖（默认 300ms）                                                         |
| `v-buttonDebounce` | `v-buttonDebounce:500="onClick"`                                                | click 事件 trailing edge 防抖（默认 500ms）                                                         |
| `v-permission`     | `v-permission="['user:edit']"`                                                  | 整页 / 整块 DOM 权限占位                                                                            |
| `v-auth`           | `v-auth="['user:create']"` 或 `v-auth:any.remove="['user:edit','user:delete']"` | 按钮级权限（AND / ANY 语义 + `disabled`/`remove` 修饰符），详见 `docs/23-权限设计.md`               |
| `v-draggable`      | `v-draggable="enabled"`                                                         | DOM 拖拽指令（钳制在视口边界内），被 `<ProDialog>` 默认消费，详见 `docs/27-ProDialog使用指南.md` §4 |

### 共享工具（`_utils.ts`）

```ts
type EventHandler = (this: HTMLElement, event: Event) => void

export function debounce(click: EventHandler, timeout: number): EventHandler { ... }
export function isFunction(param: unknown): param is (...args: unknown[]) => unknown { ... }
```

### 扩展：新指令的标准流程

1. 创建 `xxx.d.ts` 定义 `ElHTMLElement` + `XxxBinding`
2. 创建 `xxx.ts` 用 `export default { install(app) {...} }` 模式
3. 在 `index.ts` 加 `import xxx from './xxx'` + `app.use(xxx)`
4. （如需共用工具）扩 `_utils.ts`
5. CHANGELOG +1 条目 + commit

## 5. Plugins 模块详解

### 当前插件

| 插件           | 职责         | 关键能力                                                                |
| -------------- | ------------ | ----------------------------------------------------------------------- |
| `errorHandler` | 全局错误兜底 | 接管 Vue 错误 / window 错误 / Promise 拒绝；预留 `report` 回调接 Sentry |

### errorHandler 用法

```ts
// main.ts
import Plugins from '@plugins'

app.use(Plugins, {
  errorHandler: {
    // 生产环境对接 Sentry/自建日志
    report: (error, ctx) => {
      Sentry.captureException(error, { tags: { source: ctx.source } })
    },
    // dev 默认 true / prod 默认 false
    logToConsole: import.meta.env.DEV,
  },
})

// 完全关闭（罕见）
app.use(Plugins, { errorHandler: false })
```

### errorHandler 事件来源

| 来源                   | 含义                                                     |
| ---------------------- | -------------------------------------------------------- |
| `'vue'`                | Vue 组件渲染 / 生命周期抛错（`app.config.errorHandler`） |
| `'window.error'`       | window 全局 JS 错误（语法错误、未捕获异常）              |
| `'unhandledrejection'` | 未捕获的 Promise 拒绝                                    |

### 扩展：新插件的标准流程

1. 创建 `xxx.d.ts` 定义 options + 类型
2. 创建 `xxx.ts` 用 `export default { install(app, options) {...} }` 模式
3. 在 `index.ts` `PluginsOptions` 加 `xxx?: XxxOptions | false` 字段 + `app.use(xxx, options.xxx)`
4. CHANGELOG +1 条目 + commit

### 未来扩展点

| 插件               | 触发条件                                       |
| ------------------ | ---------------------------------------------- |
| `analyticsPlugin`  | 接入 GA / 百度统计 / 神策                      |
| `sentryPlugin`     | 生产环境错误监控（可替代 errorHandler.report） |
| `permissionPlugin` | 与 directives 配合做细粒度权限                 |

## 6. Alias 系统

> **架构基线更新**：2026-09-10 起，alias 配置已抽离到 `build/aliases.ts` **单一来源**，由 `build/scripts/generate-tsconfig-paths.ts` 自动同步到 `tsconfig.app.json`，**消除原先 vite.config.ts 与 tsconfig.app.json 的双维护痛点**（commit `8b7178c`）。详见 §6.1。

### 6.1 单一来源 + 自动同步

| 角色          | 文件                                        | 职责                                                                      |
| ------------- | ------------------------------------------- | ------------------------------------------------------------------------- |
| **单一来源**  | `build/aliases.ts`（`SRC_DIR_ALIASES`）     | vite 侧 + tsconfig 侧的 alias 唯一真相，15 个别名（1 个 `@` + 14 个具名） |
| vite 消费     | `vite.config.ts` → `resolveSrcDirAliases()` | 转成 `resolve.alias` 喂 Vite                                              |
| tsconfig 消费 | `build/scripts/generate-tsconfig-paths.ts`  | 读 `SRC_DIR_ALIASES` → 自动写入 `tsconfig.app.json` 的 `paths`            |
| 校验门        | `pnpm check:aliases`                        | 对比 `SRC_DIR_ALIASES` 与 `tsconfig.app.json` 的 `paths`，漂移则 CI 失败  |
| 钩子保障      | `.husky/pre-commit`                         | `pnpm generate:tsconfig-paths` 在 lint-staged 之前跑 → 提交前自动同步     |

### 6.2 当前 Alias 一览（15 个：1 个根 alias + 14 个具名子 alias）

```ts
// build/aliases.ts
export const SRC_DIR_ALIASES = {
  '@': '',
  '@api': 'api',
  '@assets': 'assets',
  '@components': 'components',
  '@composables': 'composables',
  '@directives': 'directives',
  '@enums': 'enums',
  '@layouts': 'layouts',
  '@locales': 'locales',
  '@modules': 'modules',
  '@plugins': 'plugins',
  '@router': 'router',
  '@store': 'store',
  '@types': 'types',
  '@utils': 'utils',
} as const
```

`'@'` 是根 alias（指向 `src/`），14 个具名 alias 对应 `src/<name>/`。两种用法由 tsconfig paths 同时映射（裸字符串 + 子路径），详见 §6.3。

### 6.3 为什么双映射

| 模式    | 匹配                 | 例子                                      |
| ------- | -------------------- | ----------------------------------------- |
| `XXX`   | 裸字符串（精确匹配） | `import X from '@components'`             |
| `XXX/*` | glob（任意子路径）   | `import Y from '@components/foo/Bar.vue'` |

tsconfig paths `@/*: ["./src/*"]` **不能**匹配 `@components`（裸字符串），所以每个 alias 都要写两条 paths。生成器自动展开 15 × 2 = 30 条 paths，无需手写。

### 6.4 维护规则（v2.0 之后的流程）

**新增 src 子目录时**（如新增 `src/services/`）：

1. `build/aliases.ts` 的 `SRC_DIR_ALIASES` 加 `'@services': 'services'`（**仅一处**）
2. 跑 `pnpm generate:tsconfig-paths` 自动写入 `tsconfig.app.json` 的 `paths`
3. （可选）跑 `pnpm check:aliases` 验证单一来源与产物一致
4. CHANGELOG +1 条目 + commit

> **禁止**：再手动改 `vite.config.ts` 或 `tsconfig.app.json` 的 paths——任何手动改动都会被下一次生成器覆盖或被 `pnpm check:aliases` 阻断。

## 7. main.ts 接入范式

```ts
// src/main.ts — 集中管理所有插件/指令/组件
import { createApp } from 'vue'
import App from './App.vue'
import router from '@router'
import pinia from '@store'
import i18n from '@locales'
import Directives from '@directives'
import GlobalComponents from '@components'
import Plugins from '@plugins'

// 样式（顺序：基线 → 组件库 → 工具样式 → 项目样式）
import 'normalize.css'
import 'element-plus/dist/index.css'
import 'virtual:uno.css'
import '@/assets/styles/index.scss'

const app = createApp(App)

// 核心
app.use(pinia)
app.use(router)
app.use(i18n)

// 可复用模块
app.use(GlobalComponents)
app.use(Directives)
app.use(Plugins)

app.mount('#app')
```

**原则**：

- 每个 app.use 都是一行清晰可读
- 新增 plugin/指令/组件 → main.ts 加一行
- 错误处理等散落逻辑 → 抽到 plugin

## 8. 新增模块的标准流程

### 新增指令

1. 决定指令名（kebab-case），如 `v-xxx`
2. 创建 `src/directives/xxx.d.ts`（`ElHTMLElement` + `XxxBinding`）
3. 创建 `src/directives/xxx.ts`（install 模式）
4. 编辑 `src/directives/index.ts`：import + `app.use(xxx)`
5. 跑 `pnpm lint + type-check + test + build`
6. CHANGELOG +1 + commit

### 新增插件

1. 决定插件职责（如 `analytics` / `sentry` / `permission`）
2. 创建 `src/plugins/xxx.d.ts`（`XxxOptions` + `PluginsOptions` 加字段）
3. 创建 `src/plugins/xxx.ts`（install 模式，接收 `XxxOptions`）
4. 编辑 `src/plugins/index.ts`：import + `app.use(xxx, options.xxx)`（支持 `false` 关闭）
5. 跑 `pnpm lint + type-check + test + build`
6. CHANGELOG +1 + commit

### 新增 utils 工具

1. 创建 `src/utils/xxx.ts`（纯函数 + 完整类型）
2. 创建 `src/utils/xxx.spec.ts`（Vitest 单测覆盖边界）
3. 跑 `pnpm test src/utils/xxx.spec.ts`
4. CHANGELOG +1 + commit

### 新增全局组件

1. 创建 `src/components/common/Xxx.vue`（命名 PascalCase）
2. `import.meta.glob` 自动扫描注册，**无需手动配置**
3. （如非 common 而是 layout/）手工在 `index.ts` 加 `app.use()` 或单文件 import
4. 跑 `pnpm dev` 验证 `<Xxx />` 在模板可用
5. CHANGELOG +1 + commit

### 新增 src 子目录 + alias

1. 创建 `src/<name>/` + `index.ts`
2. `vite.config.ts` 的 `SRC_DIR_ALIASES` 加 `'@<name>': '<name>'`
3. `tsconfig.app.json` 的 `paths` 加 `"@<name>"` 和 `"@<name>/*"` 两条
4. （如需要）在 main.ts 接入
5. 跑 `pnpm lint + type-check + test + build`
6. CHANGELOG +1 + commit

## 9. 验证与质量门

每个新增模块/重构完成后，**必须**跑完整套验证：

```bash
pnpm lint            # ESLint 通过
pnpm type-check      # vue-tsc 通过
pnpm test            # 87+ 测试全过
pnpm build           # vite build 通过
```

CI（如配置）会自动跑 husky pre-commit：

- lint-staged（prettier + eslint 自动修复）
- type-check:full（强制重建 .tsbuildinfo 缓存）
