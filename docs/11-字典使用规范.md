# 字典使用规范

> **什么时候用字典 store**：业务字段值是后端控制、运行时可能变动、UI 需要展示中文标签（如用户状态 / 订单状态 / 角色类型）。
> **什么时候用 `src/enums/`**：字段值是编译期常量、前端代码分支判断用（如 HTTP status code、role enum 等系统字段）。

字典系统示例：用户状态（启用/禁用/锁定）、角色（管理员/普通用户）、订单状态（待支付/已支付等）。共同特征：值由后端定义，UI 用 `el-select / el-table` 展示成中文。

> **v2 变更（2026-09）**：`useDict` 由「单 key 返回 `{ options, getLabel, refresh, loading }`」改为「**多 code 契约形态**」——一次声明多个字典，按 code 解构出独立的 `Ref<DictItem[]>`，不再提供 `getLabel` / `loading` / `options` 顶层字段。
> 原因：业务页常见「一个表单消费 3~5 个字典」，旧版多次调用、解构噪音大；新形态每个字典一个具名 Ref，模板里直接 `v-for="i in gender"`。

## 1. 三层架构速查

```
UI:    <el-select v-for="i in gender" />   <-- reactive（变化自动更新）
              ↓
Composable: useDict('gender', 'user_status') <-- 业务侧入口（一次声明多 code）
              ↓
Store:  useDictStore.fetchDict()             <-- 5min 业务层缓存 + 30s 网络层缓存
              ↓
API:    dictApi.getByType()                  <-- request<T>() 走 14 个基建
              ↓
Mock:   /api/dict/user_status                <-- vite-plugin-mock 内置
```

| 层         | 文件                         | 何时接触                          |
| ---------- | ---------------------------- | --------------------------------- |
| API        | `src/api/modules/dict.ts`    | 添加新字典 URL（一般不需要动）    |
| Mock       | `mock/dict.ts`               | 后端没接口 / 纯前端演示时加假数据 |
| Store      | `src/store/modules/dict.ts`  | 调整 PRELOAD_DICT_KEYS 预加载列表 |
| Composable | `src/composables/useDict.ts` | 业务侧**只调这个**                |

## 2. 业务侧用法（v2 多 code 契约形态）

### 2.1 核心 API

```ts
// 一次声明多个字典，按 code 解构出独立的 Ref<DictItem[]>
const { gender, user_status, refreshDict } = useDict('gender', 'user_status')
```

**返回值结构**：

| 字段          | 类型                                    | 说明                                                                 |
| ------------- | --------------------------------------- | -------------------------------------------------------------------- |
| `<code>`      | `Ref<DictItem[]>`                       | 按声明的 code 命名的 Ref 组合；template 里直接 `v-for="i in gender"` |
| `refreshDict` | `(code: string) => Promise<DictItem[]>` | 强制刷新指定 code（忽略 5min 缓存，失败降级 `[]`，不抛）             |

> **注意**：`refreshDict` 为保留字，字典 code **请勿命名**为 `'refreshDict'`，否则解构覆盖。

### 2.2 el-select 用法（最常用）

```vue
<script setup lang="ts">
// 业务侧直接声明需要的字典，类型由泛型 T 精确推导到字面量 code
const { gender, user_status } = useDict('gender', 'user_status')
</script>

<template>
  <el-select v-model="form.gender">
    <el-option v-for="i in gender" :key="i.value" :value="i.value" :label="i.label" />
  </el-select>

  <el-select v-model="form.status">
    <el-option v-for="i in user_status" :key="i.value" :value="i.value" :label="i.label" />
  </el-select>
</template>
```

### 2.3 el-table 列翻译（用 DictItem 列表找 label）

```vue
<script setup lang="ts">
const { user_status } = useDict('user_status')

// 取单项：list.find(...) 或写一个小工具包
function getLabel(list: DictItem[], value: unknown): string {
  return list.find((i) => i.value === value)?.label ?? String(value)
}

const rows = [
  { id: 1, status: 'pending' },
  { id: 2, status: 'shipped' },
]
</script>

<template>
  <el-table :data="rows">
    <el-table-column label="状态">
      <template #default="{ row }">
        {{ getLabel(user_status, row.status) }}
      </template>
    </el-table-column>
  </el-table>
</template>
```

> **替代方案**：表格列翻译推荐用 `ProTable` 的 `enum` 字段（自动渲染 ElTag），详见 [`docs/29-ProTable使用指南.md`](29-ProTable使用指南.md)。

### 2.4 强制刷新（管理员改字典后）

```ts
const { refreshDict } = useDict('user_status')

async function onDictChanged() {
  const list = await refreshDict('user_status') // 立即重发请求；失败返回 []
  console.log(`刷新后 ${list.length} 项`)
}
```

### 2.5 单 code 也能用

```ts
const { user_status } = useDict('user_status')
// ↑ 完全等价于 const { user_status, refreshDict } = useDict('user_status')
```

> **类型安全**：`useDict<T>` 泛型 T 保留调用处的 code 字面量，解构出的每个 Ref 类型精确为 `Ref<DictItem[]>`；拼写错的 code 编译期即可发现。

## 3. 缓存策略

| 层                           | 时间     | 控制                                                         | 失效时机          |
| ---------------------------- | -------- | ------------------------------------------------------------ | ----------------- |
| **网络层**（http.ts 拦截器） | 30s TTL  | `cache: { ttl: 30 }` 在 API 配置里调                         | 自动过期          |
| **业务层**（dict store）     | 5min TTL | `STORE_TTL_MS` 常量                                          | 自动过期          |
| **业务层 + force**           | 立即刷新 | `fetchDict(type, true)` 或 `useDict(code).refreshDict(code)` | 调 refreshDict 时 |

> **双层缓存的作用**：网络层防止并发请求（同一秒内多次访问只发 1 次请求）；业务层防止重复 await + 跨页面共享。
>
> **修改缓存时间**：
>
> - 网络层 TTL：改 `dict.ts` API 的 `cache.ttl`
> - 业务层 TTL：改 `dict.ts` 的 `STORE_TTL_MS`

## 4. 预加载 vs 按需加载

### 4.1 预加载（登录时自动拉）

**适用**：登录后立即需要的字典（如导航栏角色列表、首页用户状态筛选）。

修改 `src/store/modules/dict.ts` 的 `PRELOAD_DICT_KEYS`：

```ts
export const PRELOAD_DICT_KEYS: readonly string[] = [
  'user_status',
  'role',
  // 新增常用字典：
  // 'order_status',
  // 'product_category',
]
```

`src/store/modules/user.ts` 的 `login()` 已自动调用 `preloadDict()`，**业务无需手动触发**。

### 4.2 按需懒加载（默认）

**适用**：90% 的业务字典。`useDict('xxx')` 首次调用时自动拉取，5min 内复用缓存。

```ts
// 任意组件内调（v2 形态）
const { custom_dict } = useDict('custom_dict')
```

### 4.3 两者组合（推荐）

- `PRELOAD_DICT_KEYS` 列**首页 / 导航 / 高频使用**的字典
- 业务模块的低频字典走按需加载

## 5. 后端协议与扩展字段

### 5.1 返回结构

```json
{
  "code": 200,
  "message": "ok",
  "data": [
    { "value": "active", "label": "启用" },
    { "value": "inactive", "label": "禁用" }
  ]
}
```

### 5.2 扩展字段

`DictEntry` 是 index-signature 类型，业务可加任意字段（如 `color` / `disabled`）：

```ts
{ value: 'shipped', label: '已发货', color: 'primary', disabled: false }
```

业务侧读：

```ts
const { order_status } = useDict('order_status')
const entry = order_status.value.find((o) => o.value === 'shipped')
if (entry?.color) console.log(entry.color)
```

## 6. 常见坑

| 症状                               | 原因                                      | 解法                                                               |
| ---------------------------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| `el-select` 选项空白               | `xxx` 列表初始是 `[]`，fetchDict 还没完成 | 等 200ms 后再渲染；或用 `v-if="xxx.length"` 兜底                   |
| 后端改了字典 UI 没更新             | 业务层 5min 缓存 + 网络层 30s 缓存        | 调 `refreshDict(code)` 强制刷新；或浏览器 DevTools 清 localStorage |
| 切换账号后看到的还是上个账号的字典 | user store logout 没清 dict cache         | 计划任务：logout 时调 `useDictStore().clear()`                     |
| 控制台 401 不停                    | token 过期 + mock 没 `/api/auth/refresh`  | 参考 docs/10 任务 4 问题 A                                         |

## 8. 速查

```ts
// 业务侧：永远 useDict，不要直接调 dictApi
const { gender, user_status, refreshDict } = useDict('gender', 'user_status')

// 强制刷新（管理员改字典后）
await refreshDict('user_status')

// 后端联调：等真接口就绪前用 mock/dict.ts
// 新增字典：1) API 加 URL（如果有后端），2) mock/dict.ts 加假数据，3) PRELOAD_DICT_KEYS 加 key（如需预加载）

// 清缓存：登出 / 切换账号时
import { useDictStore } from '@/store/modules/dict'
useDictStore().clear()
```

## 9. 从 v1 迁移到 v2（速查）

| v1（旧）                                    | v2（新）                            | 备注                                              |
| ------------------------------------------- | ----------------------------------- | ------------------------------------------------- |
| `const { options } = useDict('x')`          | `const { x } = useDict('x')`        | 直接按 code 解构                                  |
| `getLabel(value)`                           | `x.find(i => i.value === v)?.label` | 需自己取 label（一般推荐用 ProTable `enum` 替代） |
| `loading`                                   | （无）                              | composable 层不暴露，按需自行判定                 |
| `refresh()`                                 | `refreshDict('x')`                  | 必须传 code                                       |
| `useDict('a')` + `useDict('b')`（两次调用） | `useDict('a', 'b')`（一次声明）     | 单次调用 + 多解构                                 |
