## §1 启动与运行环境（5 条）

### §1.1 一键起全站（node 网关模式）

```bash
pnpm dev:gateway
# 浏览器访问 http://localhost:8080/admin/
```

- **做什么**：node 网关 :8080 + 6 个 app（带 base）单命令同起同退。
- **为什么**：跨 app 整页跳转（登录/登出回跳）必须在同域下才能共享 cookie——这是统一登录协议运行的前置条件。`→ docs/43 §6`

### §1.2 单 app 启动（最快开发回路）

```bash
pnpm -C apps/admin dev   # 端口 5174；docs=5175 portal=5176 h5=5177 big=5178 auth=5179
```

- **做什么**：只起某一个 app，跳过 turbo 拓扑。
- **为什么**：改 admin 时不需要等 6 个 app 并行启动；mock 共享竞态也只在多 app 并行时出现。`→ docs/33`

### §1.3 演示模式（免登录）

1. 打开 `apps/admin/.env`，取消 `# VITE_DEMO_NO_AUTH=true` 的注释。
2. `pnpm -C apps/admin dev` → 直达 `/workbench`。

- **为什么**：守卫跳过登录/权限校验，方便离线演示与白盒调 UI；生产构建不会带这段逻辑（tree-shake）。

### §1.4 本地菜单模式（不依赖 mock）

```bash
pnpm -C apps/admin dev:local
```

- **做什么**：菜单读本地配置，不走 `/mock/menu`。
- **为什么**：离线/无后端时菜单也能出来；同时是排查「菜单不出来是 mock 挂了还是路由没注册」的对照组。`→ docs/33`

### §1.5 测试与构建命令族

```bash
pnpm test              # 全仓单测（turbo 拓扑序 6 app + 4 包）
pnpm test:coverage     # admin 覆盖率阈值 34/20/31/35
pnpm test:e2e          # Playwright 关键流程（首次 test:e2e:install）
pnpm bench             # vitest bench 基准（admin）
pnpm analyze           # 包体积分析（dist/stats.html，admin）
pnpm build:pages       # gh-pages 六应用聚合
pnpm build:prod        # 生产构建（注入 VITE_BUILD_ID = sha + 构建时间）
```

- **做什么**：一张表跑完「测试 → 分析 → 构建」全链路。
- **为什么**：`test:coverage` 与 `analyze` 是排障两件套（新代码缺 spec / bundle 异常增长）；`build:prod` 的 BUILD_ID 对齐 deploy.yml 语义。`→ docs/04`
- **e2e 用例清单**（`tests/e2e/`，7 个 spec）：`admin/hello` + `admin/workbench-panels`（工作台面板）/ `docs/protable-search-list` + `docs/protable-selection-batch`（ProTable 搜索/批量）/ `h5/rem-activation`（rem 激活）/ `big/layout-scale`（大屏缩放）/ `gateway/cross-app-roaming`（跨 app 漫游）。新增关键流程须同步加 spec。

## §2 看懂 workspace 拓扑（4 条）

### §2.1 6 app × 4 包一张图

```
apps/*  ──▶  packages/*
admin(5174) 中后台   config   vite 工厂 + 别名 + AutoImport 装配
docs(5175)  组件文档  mock     vite-plugin-mock 数据源
portal(5176) 门户    shared   网络层 + 全局 store + 业务 composables
h5(5177)    移动端    ui       全局组件 + 弹窗族 composables
big(5178)   数据大屏
auth(5179)  统一登录
```

- **为什么**：先看懂「谁依赖谁」再写代码——边界错误是 90% 新手代码挂掉的根因。完整拓扑 `→ docs/43`

### §2.2 依赖方向铁律（背下来）

```
apps/*  可依赖  packages/*；apps 之间 ✗ 互相 import
packages：config ∥ shared（并列上游）→ mock → ui（下游可引用上游）
运行时依赖（vue/element-plus 等）：peerDependencies + catalog 单版本源
```

- **为什么**：`eslint.config.mjs` 的 `app/boundary-*` 规则 error 级机械强制——违反即 lint 红。`→ CLAUDE.md §2.1`

### §2.3 别名 vs 包名（消费侧引用怎么写）

| 场景                                | 写法                                    |
| ----------------------------------- | --------------------------------------- |
| app 内部文件                        | `@/...`（或 `./` 相对路径）             |
| 跨包消费 `@vv/shared` / `@vv/ui`    | 包名 barrel `@vv/shared` / 显式文件路径 |
| `@api` / `@locales` / `@directives` | 别名（barrel 刻意不聚合的既定例外）     |
| `@utils/*` / `@store/*` 等深层别名  | ✗ 新代码禁止；存量渐进收敛              |

- **为什么**：别名深层路径让包边界不可见，绕过 barrel 的公共 API 收敛。`→ CLAUDE.md §1.6.2`

### §2.4 跨 app 通信协议（整页跳转）

- **做什么**：未登录守卫整页跳 `${VITE_AUTH_ORIGIN}/login?redirect=<当前地址>`，登录成功回跳。
- **为什么**：apps 之间**没有任何**共享状态/事件总线——所有跨 app 协作都通过 URL 协议 + cookie 同域漫游。`→ docs/43 §统一登录协议`

## §3 业务开发核心能力（15 条）

### §3.1 新增业务模块（脚手架）

```bash
pnpm new-module <kebab-name>   # 例：pnpm new-module orders
pnpm check:routes              # 校验路由一致性（必跑）
```

- **做什么**：自动生成 6 件套骨架（views/routes/store/apis/components/index.ts）+ 自动追加 RouteName 枚举。
- **为什么**：手写会漏文件 + 漏路由名注册；脚手架保证 check:routes 一次过。`→ docs/08`

### §3.2 路由 + 白名单

- **做什么**：路由名走 `RouteName` 枚举（`packages/shared/src/router/route-names.ts`）；公开路由按 **name** 加进 `ROUTE_WHITE_LIST`。
- **为什么**：`checkLoginState` 不读 `meta.requiresAuth`（纯类型声明）——公开访问**只能**走白名单机制。`→ docs/07`

### §3.3 useAppRouter（路由跳转唯一入口）

```ts
const { push, replace, back, pushByNameStrict } = useAppRouter()
pushByNameStrict(RouteName.OrdersList) // 名字拼错编译期报错
```

- **做什么**：业务代码**禁止** `import { useRouter } from 'vue-router'`，必须走 `useAppRouter`。
- **为什么**：ESLint `no-restricted-imports` error 级强制；`pushByNameStrict` 让路由名错误在编译期暴露而非运行时 404。`→ CLAUDE.md §1.5`

### §3.4 状态管理（4+1 分层）

| 层级                                       | 放什么                                       | 持久化        |
| ------------------------------------------ | -------------------------------------------- | ------------- |
| 全局 barrel（`@vv/shared`）                | app / dict / theme / user（4 个跨 app 共享） | `pick` 字段级 |
| admin 私有 `apps/admin/src/store/modules/` | tags-view（与 default 布局强耦合，不随迁）   | 刻意不持久化  |
| 模块私有 store                             | 本模块业务状态                               | 内存          |
| 组件 ref/computed                          | 本组件状态                                   | 内存          |

- **为什么**：tags-view 不持久化避免换账号看到老 tab；`useRouterStore`（admin 私有，store id `router-ui`，`apps/admin/src/store/modules/router.ts`）不在 `@vv/shared` barrel——由 `apps/admin/src/router/guards/remote-menu.ts` 直接消费远程菜单加载态/路由错误。`→ docs/19`

### §3.5 网络请求三件套

```ts
const { data, loading, error, isEmpty, execute } = useRequest(fetchUsers)
// 模板里：<AsyncState :loading="loading" :error="error" :is-empty="isEmpty" @retry="execute">
```

- **做什么**：业务代码**禁止**直接 `import axios`；必须走 `useRequest`（自动三态）。
- **为什么**：ESLint `no-restricted-imports` error 级强制；三态缺失会让页面永远转圈或白屏。`→ docs/17`

### §3.6 API 契约单源（zod）

- **做什么**：请求/响应契约在 `packages/shared/src/api/modules/<m>.ts` 用 zod schema 定义；运行时校验走 `requestValidated`。
- **为什么**：类型与运行时校验同源——后端字段漂移时立刻报在请求层，不流到组件。`→ docs/14`
- **高级能力**：请求层缓存/合并/分页适配（`docs/15`）+ token 自动刷新与全局取消（`docs/16`）。

### §3.7 权限三件套（useAuth + 双指令）

```vue
<script setup>
const { hasPerm, hasAnyPerm } = useAuth()
</script>
<template>
  <el-button v-if="hasPerm('orders:edit')">编辑</el-button>
  <el-button v-auth="'orders:delete'">删除</el-button>
  <div v-permission="['orders:export', 'admin']">多权限点</div>
</template>
```

- **为什么**：`v-auth` 单权限、`v-permission` 数组；权限码单源（mock 与 useAuth 同步校验）；AND 用 `hasPerm` 链式、ANY 用 `hasAnyPerm`。`→ docs/23`

### §3.8 字典 + 配套组件

```ts
const { gender, user_status, refreshDict } = useDict(['gender', 'user_status'])
// 模板：{{ gender.getLabel(row.gender) }}
```

```vue
<DictSelect v-model="form.gender" code="gender" />
<DictTag :code="user_status" :value="row.status" />
```

- **为什么**：`useDict` 多 code 契约 + 5min TTL + Promise 防抖池；配套组件 DictSelect（下拉）/ DictTag（标签）免去手写 options 映射——三件套覆盖「取数 → 渲染 → 反显」。`→ docs/11`

### §3.9 主题 useTheme

```ts
import { useTheme } from '@vv/shared' // 唯一须显式 import 的 shared composable
const { mode, primaryColor, setMode, setPrimaryColor } = useTheme()
```

- **为什么**：theme store `pick: ['mode', 'primaryColor']` 持久化；useTheme **未注入 AutoImport**（低频 API 不污染 setup 全局作用域）——这是 §3.11 AutoImport 唯一例外。`→ docs/06`

### §3.10 弹窗族三件套

| 场景       | 用谁         | 取消时的行为                                  |
| ---------- | ------------ | --------------------------------------------- |
| 命令式弹窗 | `useDialog`  | reject `DialogCancelledError`（要 try/catch） |
| 二次确认   | `useConfirm` | resolve `false`（无须 try/catch）             |
| 退出登录   | `useLogout`  | 走 `useConfirm` 路径                          |

- **为什么**：取消语义不同混用——把 `useDialog` 当 `useConfirm` 用会抛未捕获异常。`→ docs/27 §8.5`

### §3.11 全局组件族（不要显式 import）

`unplugin-vue-components` 自动注册 `packages/ui` 三目录（`components/common` + `components/ProTable` + `components/form-schema`）+ app 私有 `src/components/`——模板直接用。

| 类别     | 组件                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 数据展示 | ProTable / BaseChart / DictTag                                          |
| 表单     | XForm / form-schema（SchemaField/XFormDebugBanner）/ RichTextEditor     |
| 弹窗     | ProDialog / ProDialogForm                                               |
| 状态     | AsyncState / ErrorBoundary / ErrorPage / NetworkBanner                  |
| 应用壳   | AppShell（auth/portal/h5/big/docs 五站统一根壳；admin 刻意不用）        |
| 图标     | AppDynamicIcon（动态）+ `<i-ep-* />`（静态，unplugin-icons 编译期内联） |

- **ProTable 双引擎选型**（`tableEngine` prop，`TableEngine = 'element-plus' | 'vxe-table'`）+ **virtualized 独立 prop**：
  - `element-plus`（默认）——常规表格，生态最稳；配 `virtualized: true`（或 `VirtualScrollConfig`）走 TableV2 虚拟滚动大数据（>200 行）。
  - `vxe-table`——树形/行拖拽场景（v3.5 补齐 TreeAdapter + RowDragAdapter）。
  - **优先级**：`virtualized` 命中优先于 engine 渲染分支（virtualized > engine）。
  - **冲突三规则**：vxe + 树形 + 行拖拽同开 → console.warn + 行拖拽退化 null（sortablejs 与 vxe tree-node 行结构冲突）；`virtualized + vxe` → 自动回落 element-plus；引擎首次挂载锁定（切换需重挂载）。
  - 完整引擎契约 `→ packages/ui/src/components/ProTable/ARCHITECTURE.md`
- **ProTable 子组件族**：SearchForm / EditCell / SummaryRow / ColSetting / SelectedTags / SelectionBar / ToolbarRenderer / GroupedHeader + 三种 table body（Element / ElementV2 / Vxe）——完整 Props/Events/Slots 契约 `→ docs/29`
- **错误边界三件套**：`ErrorBoundary`（`onErrorCaptured` 拦截子组件渲染错误 + `return false` 阻断冒泡——避免被全局 errorHandler 二次上报；`emit('reset')` 通知父组件清理触发开关，否则恢复后瞬间又回错误页）+ `errorHandlerPlugin`（全局兜底，单源归 `@vv/shared`——P6 下沉收敛 5 app 85 行拷贝）+ `safeAsync` 桥接（install 时注入 report 函数，safeAsync 包装的非 HTTP 错误走同一上报通道）。
- **唯一显式 import 例外**：`<script>` 里要 `InstanceType<typeof ProTable>` 类型声明时才显式 import。
- **IDE 智能提示自检**：hover 组件只显示 `import Xxx` 字样 → 误 import 了——删掉即可恢复 props/expose/slots 提示。`→ CLAUDE.md §1.7`

### §3.12 指令族 6 个（不要 import）

| 指令                                   | 用途                   |
| -------------------------------------- | ---------------------- |
| `v-auth` / `v-permission`              | 权限点（单/数组）      |

### §3.13 utils 工具族 9 个（`@vv/shared` barrel 导出）

| 工具           | 用途                                          | 什么时候必须用                                             |
| -------------- | --------------------------------------------- | ---------------------------------------------------------- |
| `bem`          | BEM 运行时（`createNamespace` 已 AutoImport） | 每个 .vue 组件根选择器/模板 class 拼装                     |
| `dayjs`        | 日期（项目封装版，禁止裸 `import dayjs`）     | 所有日期格式化/计算（统一时区与本地化）                    |

- **为什么**：全部在 `packages/shared/src/utils/` 单源，barrel 统一导出——`@utils/*` 深层别名已收敛，新代码禁止。`→ CLAUDE.md §1.6.2`

### §3.14 i18n + 图标资产

```ts

const { t } = useI18n()
t('menu.orders')
```

- **i18n**：词典集中两文件；admin 有语言切换入口，公开五站固定 zh-cn（刻意决策非遗漏）。`→ docs/21`
- **图标**：静态 `<i-ep-xxx />`（unplugin-icons 编译期内联）/ 动态 `<AppDynamicIcon name="ep:edit" />`；本地集合 `apps/<a>/src/assets/icons/`。`→ docs/39`

### §3.15 BEM 规范（必考）

```vue
<script setup lang="ts">
const bem = createNamespace('orders-list') // kebab-case
</script>
<template>
  <div :class="bem.b()">
    <header :class="bem.e('header')" />
  </div>
</template>
<style lang="scss">
.#{$BEM_PREFIX}-orders-list {
  // 无 scoped
  &__header {
    /* ... */
  }
}
</style>
```

- **为什么**：BEM 命名空间接管隔离，`scoped` 是冗余且会破坏 `&` 编译；非 scoped 下 `:deep()` 不会被编译——覆盖第三方样式必须直接写后代选择器。`→ CLAUDE.md §3` `→ docs/05`
- **5 个高频反模式**：PascalCase 命名 / 硬编码 `vv-` 前缀 / `bem.m()` 当 element modifier 用 / 写 scoped / 在非 scoped 里写 `:deep()`。

## §4 布局与适配体系（4 条）

### §4.1 布局速选

| 布局                   | 用于                          | 路径                                  |
| ---------------------- | ----------------------------- | ------------------------------------- |
| `default`              | admin 中后台（侧边栏+多页签） | `apps/admin/src/layouts/default/`     |
| `portal`               | portal 门户（顶部水平导航）   | `apps/portal/src/layouts/portal/`     |
| `blank`                | auth 登录/落地                | `apps/auth/src/layouts/blank/`        |
| `h5`                   | h5 移动端（rem 适配）         | `apps/h5/src/layouts/h5/`             |
| `big`                  | big 大屏（scale 适配）        | `apps/big/src/layouts/big/`           |
| `DocLayout`/`DemoDocs` | docs 组件文档                 | `apps/docs/src/modules/demo/layouts/` |

- **为什么**：default 有 16 个组件（TagsView/Breadcrumb/SidebarResizer/ToolHeader/LayoutSwitcher 等）；公开五站 App.vue 退化为 `<AppShell />` 单行。布局铁律：`layouts/<m>/` 不引用 `@/components/` 或其他 layouts。`→ CLAUDE.md §1.2`

### §4.2 h5 布局 + rem 适配

- **做什么**：`packages/shared/src/plugins/remAdaptation.ts`（viewport 幂等）+ `packages/config/src/postcss.ts` 的 postcss-pxtorem **只转换** `src/layouts/h5/` 与 `src/modules/h5-*/` 前缀目录。
- **为什么**：**只转 h5 前缀目录**——其他模块写 px 不会被错转；示例模块 `apps/h5/src/modules/h5-demo/` 走免登录白名单。`→ docs/34`

### §4.3 big 布局 + scale 适配

- **做什么**：`transform: scale` 等比缩放 + 居中留白；只缩放自有容器，不碰 html/body。
- **为什么**：适配 1920/2560/4K/9000px 拼接屏——设计稿尺寸经路由 `meta.bigScreen = { width, height }` 声明（缺省 1920×1080）；超宽拼接走 `apps/big/src/modules/big-demo/wide`。`→ docs/35`

### §4.4 tags-view 多页签 + keep-alive

- **做什么**：`apps/admin/src/store/modules/tags-view.ts`（admin 私有，不在 `@vv/shared` barrel）；已访问路由列表 + keep-alive 缓存名单。
- **为什么**：**刻意不持久化**——避免换账号看到老 tab；keep-alive 名单由 tags-view 派生，路由 `meta.keepAlive` 决定是否缓存；afterEach 钩子只在 admin 挂（其他 app 的 router/index.ts 注释明确「无 tags-view afterEach」）。

## §5 Mock 与统一登录（4 条）

### §5.1 mock 双接线 + 数据模块清单

数据模块（`packages/mock/src/`）：`auth.ts` / `credentials.ts` / `dict.ts` / `dict-data.ts` / `menu.ts` / `pro-table/` / `stream.ts` / `user.ts`

- **dev**：`packages/mock/src/*.ts` 由 vite-plugin-mock 自动聚合。
- **prod（gh-pages）**：`packages/mock/src/mockProdServer.ts` **手动 import 注册**。
- **为什么**：删/加 mock 文件时三处同步摘除（import / 数组 / 注释）——漏一处 dev 看不出来，靠 `pnpm check:mock-wiring` + `type-check:full` 兜底。`→ docs/22 §15`

### §5.2 统一登录协议（整页跳转 + cookie 漫游）

- **流程**：admin 未登录 → 整页跳 `auth/login?redirect=<原地址>` → 登录成功回跳 → cookie 同域共享 → 各 app 守卫识别。
- **为什么**：cookie 是 httpOnly，前端 JS 读不到——`user store` 里的 `authenticated` 只是守卫同步判断的标记。`→ docs/23`

### §5.3 gh-pages 演示构建

```bash
pnpm build:pages   # 六应用聚合构建，产物 dist/<app>/
```

- **做什么**：自动发现 `apps/*`，按 app 注入 base 前缀 + hash 路由 + 强制 mock + local 菜单 + buildId 五开关。
- **为什么**：单仓多 app 静态托管需要各 app 独立 base——`REPO_PREFIX` 由脚本按 app 注入，不要手写。`→ docs/40`

### §5.4 stream 流式 + versionCheck 白屏兜底

- **stream 流式**：mock 的 `stream.ts` 支持 SSE 形态；前端消费走 `packages/shared/src/api/` stream 模块。`→ docs/13`
- **versionCheck**：`ChunkLoadError` 被动兜底**无条件装配**；主动轮询需注入 `onUpdate` 才启动（R3-E3 拆分启用）。
- **为什么**：发版后用户停留在旧页面 → 切路由触发 ChunkLoadError → 白屏；versionCheck 捕获后引导刷新——生产环境必备兜底。`→ CHANGELOG 未发布区 R3-E3`

## §6 排障手册（7 条）

### §6.1 五道 check 命令（跑顺序即排查顺序）

| 命令                            | 拦什么                                                        | 红了怎么修                                    |
| ------------------------------- | ------------------------------------------------------------- | --------------------------------------------- |
| `pnpm check:routes`             | 路由名/白名单/兜底三方一致 + manifest 完整性 + nginx 模板对账 | 输出自带 A/B/C/D/Nginx 修复映射，按类对号入座 |
| `pnpm check:aliases`            | tsconfig paths 与 `app-aliases.ts` 单源一致                   | 跑 `pnpm generate:tsconfig-paths` 自动收敛    |
| `pnpm check:mock-wiring`        | mock 双接线一致 + 权限码单源                                  | 三处同步（import / 数组 / 注释）              |
| `pnpm check:doc-currency`       | docs 14 项硬数据与代码一致                                    | 代码变了改文档；新增 docs 根文档 expected +1  |
| `pnpm lint` / `pnpm type-check` | ESLint / vue-tsc 增量                                         | 按报错 file:line 修                           |

- **为什么**：90% 的红落在前三门内；完整对照表（含 test:coverage/test:gateway/test:e2e 等 13 门禁）`→ docs/46`

### §6.2 高频故障对照表（症状 → 根因 → 修复）

| 症状                              | 根因                                                           | 修复                                                   |
| --------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------ |
| BEM 样式完全不生效                | `createNamespace('PascalCase')` 或 `scoped` 或缺 `lang="scss"` | 改 kebab-case + 去 scoped + 补 lang                    |
| IDE hover 组件只显示 `import Xxx` | 显式 import 了 `@vv/ui` 自动注册目录的组件                     | 删除该 import                                          |
| AutoImport 标识符报「找不到名称」 | `auto-imports.d.ts` 未生成                                     | 跑一次对应 app 的 `pnpm -C apps/<a> dev`               |
| dev 起不来，mock 相关报错         | turbo 并行 6 app 抢 mock 缓存（存量 race）                     | 用 `dev:gateway`（串行）或单 app dev                   |
| 新增菜单页面 404                  | 路由名没进 `RouteName` 枚举或白名单漏加                        | 跑 `pnpm check:routes` 看输出                          |
| `pnpm build` 报类型错但 dev 正常  | type-check:full 全量门禁 + 声明文件未生成                      | 先 `pnpm -C apps/<a> build-only` 再 type-check         |
| `vi.mock` 拦截不到 SUT 的 import  | mock 说明符与 SUT import 路径不一致                            | mock 指向同一说明符（barrel 用 `importOriginal` 展开） |
| 发版后用户白屏，刷新恢复          | 旧 chunk 被清理 + ChunkLoadError 未捕获                        | 确认 versionCheck 兜底生效（见 §5.4）                  |

- **为什么**：这些都是项目「机制性坑」而非业务 bug——修复路径已在机制里内建。`→ docs/01`

### §6.3 type-check 红了的标准流程

```bash
pnpm -C apps/admin type-check:full   # 单 app 全量，错误更全
# 逐个看报错 file:line；external 库类型问题加 declare module
# 自己代码问题改代码；改完再跑直至 0 错
```

- **为什么**：CI 干净环境必须先 `pnpm build` 再 type-check（声明文件由 build 生成）——顺序反了会报「找不到模块」假错。`→ docs/46`

### §6.4 构建报错 ≥2 次 → 触发断路器

- **做什么**：同一处修 2 次仍红 → 停止改代码，按 `docs/46` 派发 build-error-resolver 独立审查。
- **为什么**：避免第 3 次原样重试——每次修复都应有新假设，不是微调。

### §6.5 mock 相关的 type-check 假阴性

- **做什么**：dev 完全正常但 `type-check:full` 报 mock 缺类型——`mockProdServer.ts` 手动 import 的某个文件被删/改名但接线没摘。
- **为什么**：dev 走 vite-plugin-mock 自动聚合（不查 prodServer），只有 type-check:full 会触发 prodServer 编译。

### §6.6 CDP 浏览器验证（交互类 bug）

- **做什么**：交互类验证一律 CDP 输入管线（click/fill/press_key uid 级），不用合成事件。
- **为什么**：合成事件会对隐藏 popper 按钮派发导致整条验证作废——真实事件序列实践见 `docs/09` 与 `tests/e2e/` 用例。

### §6.7 ChunkLoadError 白屏排查

- **症状**：发版后部分用户页面白屏/控制台报 `ChunkLoadError`；手动刷新恢复。
- **排查**：devtools Network 看失败 chunk 是否 404（旧 HTML 引用已清理的新 chunk）；`window.addEventListener('error')` 是否捕获到。
- **修复**：确认 versionCheck 装配（见 §5.4）；引导用户刷新或开主动轮询（注入 `onUpdate`）。

## §7 扩展与发布（6 条）

### §7.1 新增应用（脚手架）

```bash
pnpm new-app <name>
```

- **做什么**：一键生成最小可 dev/build/test 的公开 app + manifest 单源注册。
- **为什么**：6 个消费方（dev-gateway/node-gateway/playwright/eslint/check-routes/createViteConfig）全部从 manifest 派生——零手改注册表。`→ CLAUDE.md v3.1.0 P2`

### §7.2 Lockdown 申请模板（结构变更必走）

```markdown
【workspace 修改申请】<方案名>

- 操作类型：[新增 app/包/删除/重命名/移动/改职责/改依赖方向]
- 目标路径：apps|packages|scripts/xxx
- 原因：[业务原因，≤2 句]
- 影响面：[影响哪些 app/包/调用方/路由/类型/turbo 拓扑]
- 备选：[是否考虑过其他归属]
- 回退：[如何恢复]
```

- **为什么**：workspace 拓扑是「结构即契约」——未经明确批准不得变更（CLAUDE.md §2.2）。**例外**：用户当轮对话明确指定文件路径 = 已预先批准（§2.3）。

### §7.3 移除业务模块（脚手架）

```bash
pnpm remove-module <kebab-name>   # 默认 dry-run + 确认
```

- **做什么**：摘除模块目录 + 路由/store/mock/菜单引用。
- **为什么**：手删会漏同步引用——脚手架保证 `check:routes` / `check:mock-wiring` 一次过。`→ scripts/remove-module.ts`

### §7.4 发布版本

```bash
pnpm release:dry   # 发布 dry-run（0 副作用，先看一眼）
pnpm release       # bump + tag + push（CHANGELOG 纯手写，发布时手工归档「未发布」段，见 docs/03）
```

- **为什么**：CHANGELOG.md 是版本口径唯一事实源（对外 semver 以根 package.json + git tag 为准）；commit message 必须中文 + 约定式前缀（feat/fix/refactor/docs/test/chore/perf）。

### §7.5 CI/CD 双流程

- **ci.yml**：PR 触发 turbo affected（`--filter=[origin/master]...`），master 全量。
- **deploy.yml**：push master 触发 `pnpm build:pages` 发布 gh-pages。
- **为什么**：affected 计算让 showroom app（docs/big/h5）只在被改时跑测试；部署 404 三连坑（Pages Source 绑定 / Environment 白名单 / 声明文件顺序）排查 `→ docs/40`

### §7.6 commitlint + 本地 ESLint 规则

- **commitlint**：commit message 中文 + 约定式前缀 + **标题 72 字符上限**（超限钩子链全跑完才拦——批次型 commit 标题控制在 ~55 字符，明细放 body）。
- **本地 ESLint 规则**：`scripts/eslint-rules/`（`package-contract` 边界规则源码）——改规则行为需同步 `pnpm test:eslint-rules`。
- **为什么**：72 字符是 commitlint 默认硬上限；本地规则有独立 spec 网守护（与 `test:check-scripts` 同性质）。`→ scripts/commitlint-formatter.cjs`
