## 任务 1：5 分钟环境准备 + 首次启动

### 1.1 工具检查

```bash
node -v    # 需要 >= 22.18 或 >= 24.12（package.json:engines）
pnpm -v    # 需要 >= 11.x
```

版本不符时报错直接看 `docs/01-工具兼容性问题踩坑记录.md`，里面有 npm vs pnpm 符号链接不兼容等问题的根因与解决。

### 1.2 启动 dev（无需接口）

```bash
git clone <repo-url> gm-portal-fe
cd gm-portal-fe
pnpm install          # 装依赖
pnpm dev:local        # 切到 local 菜单模式，无需 /api/menu 接口
```

启动成功后浏览器访问 <http://localhost:5173/login>，用 `admin / 123456` 登录。

### 1.3 dev / dev:local / build 三态速查

| 命令             | 菜单来源         | Mock             | 适用场景                               |
| ---------------- | ---------------- | ---------------- | -------------------------------------- |
| `pnpm dev`       | `remote`（默认） | vite-plugin-mock | 调试与生产一致性的真实流程             |
| `pnpm dev:local` | `local`          | vite-plugin-mock | 无后端时联调，纯前端开发               |
| `pnpm build`     | -                | prod 关闭        | 验证 TS 类型 + 产线构建                |
| `pnpm analyze`   | -                | -                | 构建 + 输出 dist/stats.html 包体积分析 |

## 任务 2：加一个新静态页面（用 `pnpm new-module`）

> 适用：纯展示页面（如运营页 / 关于页 / 帮助页），没有后端数据。

### 2.1 一行命令生成骨架

```bash
pnpm new-module about
```

**自动产出**（看 `scripts/new-module.ts`）：

```
src/modules/about/
├── views/Index.vue          # 入口视图（BEM 样式骨架）
├── routes/index.ts          # default layout 包装，自动注册
├── store/index.ts           # Setup Store 骨架（含 draft/setDraft/clearDraft 示例）
├── apis/index.ts            # 模块本地 API 层（含 PascalItem 类型 + <name>Api getList 占位）
├── components/.gitkeep      # 放业务组件的目录
└── index.ts                 # 模块对外接口 stub
```

外加：`src/router/types.ts` 的 `RouteName` 联合类型自动追加 `'About'`。

### 2.2 启动查看

```bash
pnpm dev:local
# 浏览器访问 http://localhost:5173/about
```

### 2.3 跑一次一致性校验（CI 阶段会强制）

```bash
pnpm check:routes
```

预期看到 `✓ 所有路由检查通过`。

### 2.4 想改页面标题 / icon

编辑 `src/modules/about/routes/index.ts` 的 `meta`：

```ts
meta: {
  title: '关于我们',
  titleKey: 'menu.about',   // 国际化时改这里，title 作 fallback
  icon: 'info-filled',       // Element Plus 图标名
  requiresAuth: true,
  // permissions: ['about:view'],  // 路由级权限
}
```

涉及 i18n 时同时在 `src/locales/{zh-CN,en-US}.ts` 的 `menu` 段加 `'about': '关于我们'`。

### 2.5 进一步参考

- 多级菜单（带子页）：参考 `src/modules/orders/routes/index.ts`
- blank layout（登录页）：参考 `src/modules/auth/routes/index.ts`
- 完整路由流程图：见 [`docs/07-路由模块设计.md`](./07-路由模块设计.md)

## 任务 3：加一个完整业务页面（权限 + 异步三态 + i18n + 表单）

> 适用：CRUD 列表 / 详情页 / 配置页。**最常写的页面类型**。

### 3.1 生成骨架（同任务 2）

```bash
pnpm new-module equipment
```

### 3.2 完善 API 模块

第 2 任务已生成 `src/modules/equipment/apis/index.ts`（含 `EquipmentItem` 类型与 `equipmentApi.getList` 占位）。继续按业务填写：

```ts
import { request } from '@/api/http'

export interface EquipmentItem {
  id: number
  name: string
  status: 'active' | 'inactive'
}

export const equipmentApi = {
  getList: (params: { page: number; pageSize: number; keyword?: string }) =>
    request<Pagination<EquipmentItem>>({
      url: '/equipment/list',
      method: 'get',
      params,
      usePageAdapter: true, // 自动按项目约定的分页协议转换
    }),
}
```

`src/modules/<m>/apis/index.ts` 与 `src/api/modules/<m>.ts` **互斥**：

- 仅本模块使用（强内聚）→ 用脚手架生成的 `apis/`
- 跨模块共享（多页面共用同接口）→ 把 `apis/` 整文件迁到 `src/api/modules/<m>.ts`，代码零改动

### 3.3 写 mock 数据

`mock/equipment.ts`：

```ts
import { defineMock } from 'vite-plugin-mock/utils'

export default defineMock([
  {
    url: '/api/equipment/list',
    method: 'get',
    // 注意：mock 函数必须是同步的（vite-plugin-mock 不支持 async response）
    // 延迟用 timeout 字段控制
    timeout: 200,
    body: ({ query }) => ({
      data: {
        list: Array.from({ length: 5 }, (_, i) => ({
          id: i + 1,
          name: `设备 ${i + 1}`,
          status: i % 2 ? 'active' : 'inactive',
        })),
        total: 5,
      },
    }),
  },
])
```

### 3.4 视图层：异步三态封装

`src/modules/equipment/views/List.vue`：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { useI18n } from 'vue-i18n'
import { useRequest } from '@/composables/useRequest'
import { equipmentApi, type EquipmentItem } from '@/api/modules/equipment'

const { t } = useI18n()
const keyword = ref('')

// useRequest 提供 { data / loading / error / isEmpty / refresh / cancel } 三态封装
const { data, loading, error, isEmpty, refresh } = useRequest(
  () => equipmentApi.getList({ page: 1, pageSize: 20, keyword: keyword.value }),
  { watch: [keyword] } // 关键词变化自动重拉
)

const rows = computed<EquipmentItem[]>(() => data.value?.list ?? [])
</script>

<template>
  <AsyncState :loading="loading" :error="error" :is-empty="isEmpty" @retry="refresh">
    <!-- 关键表格组件，从 src/components/common/ 找通用封装 -->
    <el-table :data="rows">
      <el-table-column :label="t('equipment.name')" prop="name" />
      <el-table-column :label="t('equipment.status')" prop="status" />
    </el-table>
  </AsyncState>
</template>
```

### 3.5 权限控制（v-auth 按钮 / v-permission 整页）

```vue
<template>
  <!-- 整页权限（路由级：meta.permissions） -->
  <div v-permission="['equipment:view']">
    <!-- 按钮级（支持 :any.disabled / :any.remove 修饰符） -->
    <el-button v-auth="['equipment:create']" type="primary">新增</el-button>
    <el-button v-auth:any.remove="['equipment:edit', 'equipment:delete']">编辑/删除</el-button>
  </div>
</template>
```

权限码定义在 `mock/auth.ts` 的 `permissions` 字段，业务运行时从 `useUserStore().permissions` 读。

### 3.6 进阶

| 场景                     | 参考                                              |
| ------------------------ | ------------------------------------------------- |
| 文件上传 / 流式响应      | `src/api/stream.ts`                               |
| 401 自动 refresh + retry | 默认开，看 `src/api/http.ts:request<T>()`         |
| 表单（受控）+ 表单校验   | Element Plus `el-form` + 项目封装（无项目级封装） |
| 多页签 keepAlive         | `meta.keepAlive: true`                            |
| 树表 / 虚拟滚动          | Element Plus 自带 + 项目未封装                    |

### 3.7 强制使用项目封装（ESLint 规则）

业务代码（`src/modules/**`、`src/components/**`、`src/views/**`）必须走项目封装，禁止直接调用底层 API。违规时 ESLint 输出 warning，IDE 实时提示。

| 禁止                                     | 推荐替代                                                   |
| ---------------------------------------- | ---------------------------------------------------------- |
| `import { useRouter } from 'vue-router'` | `import { useAppRouter } from '@composables/useAppRouter'` |
| `import axios from 'axios'`              | `import { useRequest } from '@composables/useRequest'`     |

**为什么这样设计？**

- `useAppRouter` 集中错误处理（toast）、i18n title 写入、类型安全的按 name 跳转、history fallback
- `useRequest` 统一三态管理（loading / error / empty）、请求竞态保护、AbortController
- 直接调用底层 API 会绕过这些保护，埋下运行时 bug

**白名单位置（天然不受限制）：**

- `src/composables/**`（封装自身实现）
- `src/router/**`（路由守卫、动态路由）
- `src/plugins/**`（插件初始化）
- `src/main.ts`、`src/App.vue`
- `*.spec.ts`（测试用例）

> `useRoute`（读取当前路由状态）不在拦截范围，vue-router 的只读 API 业务侧有持续需求。

## 任务 4：调常见问题

### 问题 A：401 不停刷新，登录后没法调通

**症状**：每次调接口都触发 `token-refresh`，刷新后又 401，循环。

**排查**：

```bash
# 1. 看后端返回的 status code
#    Chrome DevTools → Network → 看 /api/auth/refresh 的 response
# 2. 看前端拦截器走的是哪条分支
```

**代码路径**：

- `src/api/http.ts:request<T>()` 自动捕获 401 + `!config._retried` 触发 refresh
- 第二次 401 → `performLogout()` → toast + 清 token + 跳 `/login`
- 检查 `src/api/token-refresh.ts` 的 `getValidToken()` 是否正确处理并发

**对照清单**：

- [ ] `pnpm dev` / `pnpm dev:local` 均处于开发模式，Mock 由 `vite.config.ts` 自动启用；`dev:local` 只切换菜单来源为 local
- [ ] `mock/auth.ts` 的 `permissions` 是否包含本页面所需权限码

### 问题 B：主题切换不生效 / 双主题布局错乱

**症状**：调用 `useTheme().setMode('dark')` 后颜色没变，或局部元素没切换。

**排查**：

1. 自定义元素是否用了 `var(--bg-*)` 等主题感知变量？参考 `docs/06-主题管理规范.md` 速查表
2. 主题 store 是否被持久化？清 `localStorage.gm-portal-fe:theme-mode` 后重试
3. Element Plus 组件需要 CSS 变量覆盖，看 `src/assets/styles/element-overwrite.scss`

### 问题 C：远程菜单 404，sidebar 看不到新页面

**症状**：登录成功但 sidebar 没出现预期菜单项。

**排查顺序**：

```
1. DevTools Network 看 /api/menu 响应
   ↓ 200 + 列表里有你的模块 → 继续
   ↓ 404 → 打开 src/router/config.ts 看菜单模式（remote / local）
                ↓
       remote 时需要 mock 路由：mock/menu.ts 配一下
       local  → 直接看 src/router/auto-register.ts 自动注册结果

2. pnpm check:routes 一致性校验（type / whitelist / 路由 三处）

3. 组件权限被拒绝？v-permission 把整页 hide 了？

4. 菜单项 hidden=true？后端菜单协议的 hidden → 前端 meta.visible:false
```

### 问题 D：API 数据格式不对（分页 / 时间戳 / 字段名）

**症状**：后端返回 `{ records: [...], total: 100 }`，前端期望 `{ list: [...], total: 100 }`。

**解决**：

```ts
// src/api/page-adapter.ts 提供可配置的字段映射
configurePaginationAdapter({
  request: { page: 'pageNum', pageSize: 'pageSize' }, // 请求字段名
  response: { list: 'records', total: 'total' }, // 响应字段名
})
```

调用 `request<T>({ ..., usePageAdapter: true })` 即可双向转换。

### 问题 E：本地能跑但 build 后页面 404

**症状**：`pnpm dev` 一切正常，`pnpm build && pnpm preview` 后访问某页面 404。

**根因**：静态托管未配置 SPA fallback（history 模式下所有 404 应 fallback 到 `/index.html`）。

**修复**（Nginx 示例）：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

详细 Docker / Nginx 部署模板见 README §部署章节。
