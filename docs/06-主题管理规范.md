## 📋 架构总览

```mermaid
flowchart LR
    A[用户操作<br/>设置/系统切换] --> B[useTheme composable]
    B --> C[Pinia theme store]
    C --> D[localStorage<br/>持久化]
    C --> E[document.documentElement<br/>setAttribute data-theme]
    E --> F[CSS 变量切换<br/>var(--bg-base) 等]
    F --> G[全站样式自动跟随]

    H[Element Plus 组件] --> I[--el-color-xxx<br/>SCSS color.mix 计算]
    I --> F
```

### 三层职责分离

| 层           | 文件                                                         | 职责                                                                           |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| **变量层**   | `src/assets/styles/variables.scss`                           | 主题无关常量（品牌色 / 间距 / 圆角 / 字号 / 阴影 / z-index / 动画时长 / 缓动） |
| **主题层**   | `src/assets/styles/theme.scss`                               | 主题感知变量（背景 / 文字 / 边框），定义 light + dark 两套值                   |
| **运行时层** | `src/store/modules/theme.ts` + `src/composables/useTheme.ts` | 状态管理 + 持久化 + 切换 API                                                   |

## 🎯 设计决策：为什么用 CSS 变量

### 对比表

| 维度        | SCSS 编译期方案                                  | **CSS 变量方案（采纳）**             |
| ----------- | ------------------------------------------------ | ------------------------------------ |
| 运行时切换  | ✅ `setAttribute('data-theme')`                  | ✅ `setAttribute('data-theme')`      |
| Bundle 体积 | ❌ N 主题 × 组件样式（每主题重复规则）           | ✅ 1 套规则 + 变量值切换             |
| 新增主题    | ❌ 必须重新编译 SCSS                             | ✅ 运行时 JS 注入 CSS                |
| Pinia 集成  | ⚠️ 只能切属性                                    | ✅ 切属性 + 改 :root 变量            |
| 跨主题共享  | ❌ 每个主题都要写                                | ✅ `var(--primary, var(--fallback))` |
| 第三方组件  | ❌ Element Plus 用 CSS 变量，需再覆盖            | ✅ `--el-color-xxx` 直接映射         |
| TS 类型     | ❌ 字符串键名无校验                              | ✅ IDE 插件可补全                    |
| 调试        | ⚠️ DevTools 看 html[data-theme='xxx'] .container | ✅ DevTools 看 `--bg-base` 当前值    |

**结论**：CSS 变量方案被 Element Plus / Vant / Naive UI / Ant Design Vue 等主流 Vue 3 UI 库选用，bundle 体积、新增主题灵活性、与第三方组件兼容性都更优。

## 🔌 切换 API（`useTheme` composable）

```ts
// src/composables/useTheme.ts（已实现）
const { mode, isDark, setMode, toggleMode } = useTheme()
```

### API 详解

| API              | 类型                               | 说明                                              |
| ---------------- | ---------------------------------- | ------------------------------------------------- |
| `mode`           | `Ref<'light' \| 'dark' \| 'auto'>` | 当前模式（响应式）                                |
| `isDark`         | `Ref<boolean>`                     | 当前是否为深色（响应式，含 auto + 系统）          |
| `setMode(value)` | `(value: ThemeMode) => void`       | 显式设置模式                                      |
| `toggleMode()`   | `() => void`                       | 智能切换（auto + 系统深色 → light；light → dark） |

### 持久化

`mode` 字段自动写入 localStorage（key: `theme-mode`），刷新页面保留用户选择。

### 跟随系统

`mode === 'auto'` 时，store 自动监听 `prefers-color-scheme` 媒体查询，系统主题变化时 `isDark` 自动同步。

## 🧩 组件写法（4 种场景）

### 场景 1：主题感知（90% 默认场景）

**需求**：组件样式跟随主题色变化。

**写法**：直接用 CSS 变量，**零额外代码**。

```vue
<!-- src/modules/user/components/UserCard.vue -->
<template>
  <div :class="bem.b()">
    <h3 :class="bem.e('name')">{{ user.name }}</h3>
    <p :class="bem.e('email')">{{ user.email }}</p>
  </div>
</template>

<style lang="scss" scoped>
@use '@/assets/styles/mixins/bem' as *;

.user-card {
  @include b(user-card) {
    padding: var(--spacing-md);
    border-radius: var(--radius-md);
    background: var(--bg-base); /* 主题感知：light 白 / dark 黑 */
    color: var(--text-primary); /* 主题感知 */
    border: 1px solid var(--border-base);
    box-shadow: var(--shadow-sm);
    transition: all var(--duration-normal) var(--ease-out);
  }

  @include e(name) {
    font-size: var(--font-size-md);
    font-weight: var(--font-weight-semibold);
  }

  @include e(email) {
    font-size: var(--font-size-sm);
    color: var(--text-regular);
  }
}
</style>
```

---

### 场景 2：某个主题专属样式（结构差异）

**需求**：浅色主题有边框，深色主题有渐变——结构差异而非单纯颜色差异。

**写法**：用 `[data-theme='xxx']` 选择器。

```vue
<style lang="scss" scoped>
@use '@/assets/styles/mixins/bem' as *;

.user-card {
  @include b(user-card) {
    padding: var(--spacing-md);
    border-radius: var(--radius-md);
    background: var(--bg-base);
    color: var(--text-primary);
    transition: all var(--duration-normal) var(--ease-out);

    /* 浅色主题：实线边框 */
    [data-theme='light'] & {
      border: 1px solid var(--border-base);
    }

    /* 深色主题：渐变背景 + 阴影 */
    [data-theme='dark'] & {
      background: linear-gradient(135deg, var(--bg-base), var(--bg-secondary));
      box-shadow: var(--shadow-md);
    }
  }
}
</style>
```

**关键点**：

- `[data-theme='xxx']` 是**全局属性选择器**（挂在 `<html>` 上）
- Vue `<style scoped>` 编译时会自动加 `[data-v-xxx]`，最终选择器是 `[data-theme='light'] .user-card[data-v-xxx]`
- 父选择器 `&` 在 `[data-theme='light']` 块内指向 `.user-card`，SCSS 嵌套展开

### 场景 3：JS 动态控制（条件渲染）

**需求**：根据 `isDark` 状态动态加 class、显示不同图标、触发动画。

**写法**：用 `useTheme()` composable + 运行时 BEM 工具的状态类。

```vue
<script setup lang="ts">
import { useTheme } from '@composables/useTheme'
import { createNamespace } from '@utils/bem'

interface Props {
  user: { name: string; email: string }
}
defineProps<Props>()

const { isDark } = useTheme()
const bem = createNamespace('user-card')
</script>

<template>
  <div :class="[bem.b(), bem.is('dark', isDark)]">
    <h3 :class="bem.e('name')">{{ user.name }}</h3>
    <i :class="[bem.e('icon'), isDark ? 'icon-moon' : 'icon-sun']" />
  </div>
</template>

<style lang="scss" scoped>
@use '@/assets/styles/mixins/bem' as *;

.user-card {
  @include b(user-card) {
    padding: var(--spacing-md);
    background: var(--bg-base);

    @include is(dark) {
      background: linear-gradient(135deg, var(--bg-base), var(--bg-secondary));
      box-shadow: var(--shadow-lg);
    }
  }

  @include e(icon) {
    font-size: var(--font-size-lg);
  }
}
</style>
```

**关键点**：

- `bem.is('dark', isDark)` 在 `isDark=true` 时返回 `'is-dark'`，Vue 自动应用
- SCSS 中 `@include is(dark)` 编译为 `.user-card.is-dark`，与运行时类名一一对应
- **CSS 变量控制颜色切换，状态类控制是否启用额外样式**——两者互补

---

### 场景 4：跨主题共享（品牌色）

**需求**：所有主题下 `--color-primary` 都是同一个品牌色。

**写法**：放在 `variables.scss` 的 `:root` 中（不带 `[data-theme]` 选择器），保持现状。

```scss
// variables.scss
:root {
  --color-primary: #409eff; // 所有主题共用
  --color-success: #67c23a;
  --color-warning: #e6a23c;
  --color-danger: #f56c6c;
}
```

主题切换时，品牌色不变，只换 `--bg-base` / `--text-primary` 等主题感知变量。

## 🚀 扩展指南：新增主题

### 示例：新增 `sepia`（护眼）主题

#### 步骤 1：在 `theme.scss` 添加 mixin

```scss
@mixin theme-sepia {
  --bg-base: #f4ecd8;
  --bg-secondary: #e8dcc0;
  --bg-tertiary: #ebdfc6;

  --text-primary: #5b4636;
  --text-regular: #7a6552;
  --text-secondary: #9c8770;
  --text-placeholder: #b8a890;

  --border-base: #d4c4a8;
  --border-light: #c8b898;
  --border-lighter: #bca888;
  --border-extra-light: #b09878;
}
```

#### 步骤 2：注册选择器

```scss
[data-theme='sepia'] {
  @include theme-sepia;
}
```

#### 步骤 3：（可选）跟随系统

```scss
@media (prefers-color-scheme: sepia) {
  :root:not([data-theme]) {
    @include theme-sepia;
  }
}
```

#### 步骤 4：扩展 `ThemeMode` 类型

```ts
// src/store/modules/theme.ts
export type ThemeMode = 'light' | 'dark' | 'sepia' | 'auto'
```

#### 步骤 5：（可选）业务组件中提供切换 UI

```vue
<el-radio-group v-model="mode" @change="setMode">
  <el-radio-button value="light">浅色</el-radio-button>
  <el-radio-button value="dark">深色</el-radio-button>
  <el-radio-button value="sepia">护眼</el-radio-button>
  <el-radio-button value="auto">跟随系统</el-radio-button>
</el-radio-group>
```

**完成**：无需重新打包组件，主题切换能力即刻生效。

## 🎨 品牌色 vs Element Plus 默认色关系

> 业务侧改 `VITE_BRAND_COLOR` 即可全局生效（含 Element Plus 组件），但需要理解三层叠加关系。

### 三层覆盖关系

```
Layer 1（最优先）：src/main.ts 启动时
  document.documentElement.style.setProperty('--color-primary', VITE_BRAND_COLOR || '#409eff')
  ↓ 覆盖 CSS 变量
Layer 2：src/assets/styles/variables.scss
  $color-primary: #409eff  // SCSS 变量（编译期）
  ↓ 注入到 :root[data-theme]
Layer 3：Element Plus 默认色
  --el-color-primary: #409eff  // 灯色阶基础
```

### 改品牌色后会发生什么

| 改动                                                   | 影响范围                                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `VITE_BRAND_COLOR=#ff6b35`                             | 所有 `--color-primary` 引用处 + Element Plus 灯色阶（5 主色 × 5 阶 = 25 个变量） |
| `src/assets/styles/variables.scss` 改 `$color-primary` | SCSS 编译期变量（如业务方硬编码 `color: $color-primary` 的地方）                 |
| Element Plus 主题覆盖                                  | 仅 Element Plus 组件内的具体场景（不影响业务自定义组件）                         |

### 推荐工作流

```bash
# 1. .env.local 加品牌色
VITE_BRAND_COLOR=#ff6b35

# 2. 重启 dev（VITE_ 环境变量变更需要重启）
pnpm dev

# 3. 检查三个场景
- 业务组件（Button.vue 等）：应看到品牌色
- Element Plus 组件（el-button primary）：应看到品牌色灯色阶
- 主题切换（dark mode）：品牌色在暗色下应自动调整对比度

# 4. 若需彻底品牌定制（不仅主色）
修改 src/assets/styles/element-overwrite/index.scss 的灯色阶 mixin
```

### ⚠️ 注意事项

1. **品牌色必须在 createApp 之前应用**：否则首屏闪烁（unocss / Element Plus 组件先渲染默认色再被覆盖）
2. **Element Plus 升级时检查灯色阶 mixin**：2.x → 3.x 可能调整色阶算法，需要重新校验
3. **暗色主题下品牌色对比度**：避免选择过亮/过暗的品牌色（WCAG AA 要求文本对比度 ≥ 4.5:1）

### 验证脚本

```bash
# dev 模式打开浏览器 Console，运行：
getComputedStyle(document.documentElement).getPropertyValue('--color-primary')
// 应返回 VITE_BRAND_COLOR 设定的值

getComputedStyle(document.documentElement).getPropertyValue('--el-color-primary')
// Element Plus 灯色阶基础色（应与 --color-primary 一致）
```

## ❓ FAQ

### Q1：为什么不用 SCSS 编译期生成多套主题规则？

**A**：两种方案运行时切换效果相同，但 CSS 变量方案 bundle 体积更小、新增主题更灵活（无需重新编译）。Element Plus / Vant / Naive UI 等主流 Vue 3 UI 库均采用 CSS 变量方案。

### Q2：`isDark` 和 `data-theme="dark"` 有什么区别？

**A**：

- `data-theme="dark"` 是 `<html>` 上的属性，CSS 选择器用它匹配主题样式
- `isDark` 是 JS 层的响应式布尔值（`useTheme()` composable 暴露）
- 前者用于 CSS 匹配，后者用于 JS 条件渲染（v-if / :class）

### Q3：`prefers-reduced-motion` 与主题切换冲突吗？

**A**：不冲突。`prefers-reduced-motion` 控制动画，`data-theme` 控制颜色变量。两者可叠加生效：

- 主题切换时若 `prefers-reduced-motion: reduce`，应跳过颜色过渡动画（CSS `transition: background-color 0s`）

### Q4：如何在 Element Plus 弹窗等组件中跟随主题？

**A**：已自动跟随。`element-overwrite.scss` 用 SCSS `color.mix()` 计算 `--el-color-primary-light-3/5/7/8/9`，Element Plus 弹窗背景/边框/文字色全部引用这些变量，主题切换时自动跟随。

### Q5：能运行时新增主题吗？

**A**：可以。在 `theme.scss` 编译期注册所有候选主题的 mixin 后，运行时 JS 仅需切换 `data-theme` 属性即可激活。无需重新打包。如果主题需要完全动态（如用户自定义色），可扩展为 `useTheme()` 接收用户颜色，注入 `<style>` 标签（超出本规范范围）。

### Q6：`useTheme()` 在 SSR 环境下能用吗？

**A**：`theme store` 已做 SSR 保护（`typeof document === 'undefined'` 时跳过 DOM 操作）。但 `localStorage` 在 SSR 阶段不可用，需在客户端 hydration 后才生效。建议 SSR 渲染默认主题，hydration 后再应用用户偏好。
