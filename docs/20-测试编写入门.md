> **配套文档**：`docs/04-构建与测试工具.md`（配置文件）+ `docs/19-Pinia store使用规范.md` §6（store 测试模板）

## 1. 三件套总览

| 工具                | 作用                                     | 项目配置                                 |
| ------------------- | ---------------------------------------- | ---------------------------------------- |
| **Vitest**          | 测试运行器（jest 兼容 API，更快）        | `vitest.config.ts`                       |
| **@vue/test-utils** | Vue 组件挂载 + props/emit 断言           | 自动通过 `unplugin-vue-components`       |
| **jsdom**           | 浏览器环境模拟（DOM API + localStorage） | `vitest.config.ts: environment: 'jsdom'` |

**常用命令**（Monorepo 双栏口径——根目录脚本与单 app 脚本不同源）：

| 场景                                                | 命令                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------ |
| 根目录·全量单测（turbo 拓扑序 6 app + 4 包，CI 用） | `pnpm test`                                                              |
| 根目录·覆盖率报告（admin 口径，输出到 coverage/）   | `pnpm test:coverage`                                                     |
| 根目录·e2e（Playwright，tests/e2e/，详见 docs/04）  | `pnpm test:e2e`（首次先 `pnpm test:e2e:install`）                        |
| 单 app·全量单测                                     | `pnpm -C apps/<a> test`                                                  |
| 单 app·watch 模式（开发用）                         | `pnpm -C apps/<a> test:watch`                                            |
| 单 app·跑指定目录/文件                              | `pnpm -C apps/<a> test src/utils` / `pnpm -C apps/<a> test user.spec.ts` |

> ⚠️ 根目录没有 `test:watch` 脚本，且根 `pnpm test` = `turbo run test`，位置参数无法按 vitest 语义透传——watch / 按路径跑必须走 `pnpm -C apps/<a> ...`。

## 2. 文件命名与组织

**约定**：测试文件与源码同级，命名为 `<name>.spec.ts`（主力 utils / composables 在 `packages/shared`，全局组件在 `packages/ui`；6 个 app 内部 `apps/<a>/src/...` 同理）：

```
packages/shared/src/utils/
├── dayjs.ts
├── dayjs.spec.ts          ← 源码 + spec 同级
├── format.ts
└── format.spec.ts

packages/shared/src/composables/
├── useRequest.ts
├── useRequest.spec.ts
└── useLogout.spec.ts

packages/ui/src/components/common/
├── AsyncState.vue
└── AsyncState.spec.ts     # 组件 spec 与组件同级（common/ 下组件平铺，无子目录）
```

> ❌ 错误：`__tests__/` 目录集中放测试文件 → 与源码分离，难以维护。

## 3. AAA 模式（Arrange-Act-Assert）

每个测试用例按三段式组织：

```ts
it('用例描述（具体行为）', () => {
  // Arrange：准备数据 + mock + 初始化
  const input = { name: 'test' }
  const mockApi = vi.fn().mockResolvedValue({ id: 1 })

  // Act：执行被测函数
  const result = computeName(input)

  // Assert：断言结果
  expect(result).toBe('TEST')
  expect(mockApi).toHaveBeenCalledOnce()
})
```

**优势**：

- 测试意图清晰（看 `Act` 知道测什么）
- 失败信息精准（哪一段挂了）
- 易于重构（边界条件改动只需动 `Assert`）

## 4. 模板 1：utils 纯函数测试

```ts
// packages/shared/src/utils/dayjs.spec.ts
import { describe, it, expect } from 'vitest'
import { formatDate, formatRelative } from './dayjs'

describe('formatDate', () => {
  it('格式化 Date 对象为 YYYY-MM-DD', () => {
    const date = new Date('2026-07-24T08:00:00Z')
    expect(formatDate(date, 'YYYY-MM-DD')).toBe('2026-07-24')
  })

  it('接受字符串输入', () => {
    expect(formatDate('2026-07-24', 'YYYY/MM/DD')).toBe('2026/07/24')
  })

  it('接受数字时间戳', () => {
    expect(formatDate(Date.now(), 'YYYY')).toMatch(/^\d{4}$/)
  })

  it('默认 pattern 是 YYYY-MM-DD HH:mm:ss', () => {
    expect(formatDate('2026-07-24 08:00:00')).toBe('2026-07-24 08:00:00')
  })

  it('无效输入返回 Invalid Date', () => {
    expect(formatDate('not-a-date')).toBe('Invalid Date')
  })
})

describe('formatRelative', () => {
  it('过去时间返回「X 分钟前」（显式传 zh-CN locale）', () => {
    const fiveMinAgo = Date.now() - 5 * 60 * 1000
    expect(formatRelative(fiveMinAgo, 'zh-CN')).toBe('5 分钟前')
  })

  it('未来时间返回「X 天后」（显式传 zh-CN locale）', () => {
    const tomorrow = Date.now() + 24 * 60 * 60 * 1000
    expect(formatRelative(tomorrow, 'zh-CN')).toBe('1 天后')
  })
})
```

**要点**：

- 无需 `setActivePinia` / 无需 `mount` / 无需 mock
- 边界条件：有效输入、无效输入、空值、极值
- 一个 `describe` 对应一个函数，多个 `it` 对应多个 case

## 5. 模板 2：composable 测试（含 Vue 上下文）

```ts
// packages/shared/src/composables/useRequest.spec.ts
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { useRequest } from './useRequest'
import * as api from '@api/modules/equipment'

vi.mock('@api/modules/equipment', () => ({
  equipmentApi: {
    getList: vi.fn(),
  },
}))

describe('useRequest', () => {
  beforeEach(() => {
    vi.clearAllMocks()
  })

  it('首次调用立即触发 fetcher', async () => {
    vi.mocked(api.equipmentApi.getList).mockResolvedValue({
      data: { list: [], total: 0 },
    } as never)

    const { data, loading } = useRequest(() => api.equipmentApi.getList({ page: 1, pageSize: 20 }))

    expect(loading.value).toBe(true)
    await vi.dynamicImportSettled() // 等异步完成

    expect(data.value).toEqual({ list: [], total: 0 })
    expect(loading.value).toBe(false)
  })

  it('fetcher 抛错时 error 捕获', async () => {
    vi.mocked(api.equipmentApi.getList).mockRejectedValue(new Error('网络异常'))

    const { error, loading } = useRequest(() => api.equipmentApi.getList({ page: 1, pageSize: 20 }))

    await vi.dynamicImportSettled()

    expect(error.value).toBeTruthy()
    expect(loading.value).toBe(false)
  })

  it('watch 触发时自动重拉', async () => {
    vi.mocked(api.equipmentApi.getList).mockResolvedValue({ data: [] } as never)

    const keyword = ref('')
    const { data } = useRequest(
      () => api.equipmentApi.getList({ page: 1, pageSize: 20, keyword: keyword.value }),
      { watch: [keyword] }
    )

    expect(api.equipmentApi.getList).toHaveBeenCalledTimes(1)

    keyword.value = 'test'
    await vi.dynamicImportSettled()

    expect(api.equipmentApi.getList).toHaveBeenCalledTimes(2)
    expect(api.equipmentApi.getList).toHaveBeenLastCalledWith({
      page: 1,
      pageSize: 20,
      keyword: 'test',
    })
  })
})
```

**要点**：

- `vi.mock('@api/...')` 在文件顶部声明，自动 hoist；**mock 说明符必须与 SUT 的 import 说明符同路径**（SUT 从 `@vv/shared` import，mock 就写 `'@vv/shared'`；说明符不同则失去拦截）——这是 Monorepo 收敛后的高频坑（CLAUDE.md §1.6.2-4）
- `vi.clearAllMocks()` 在 `beforeEach` 重置 mock 计数
- `await vi.dynamicImportSettled()` 等异步操作完成（替代 `nextTick`）
- composable 内 `ref` / `computed` 自动响应式

## 6. 模板 3：Vue 组件测试（@vue/test-utils mount）

```ts
// packages/ui/src/components/common/AsyncState.spec.ts
import { describe, it, expect } from 'vitest'
import { mount } from '@vue/test-utils'
import AsyncState from './AsyncState.vue'

describe('AsyncState.vue', () => {
  it('loading=true 时显示 spinner', () => {
    const wrapper = mount(AsyncState, {
      props: { loading: true, error: null, isEmpty: false },
      slots: { default: '<div class="content">CONTENT</div>' },
    })

    expect(wrapper.find('[data-testid="loading"]').exists()).toBe(true)
    expect(wrapper.find('.content').exists()).toBe(false)
  })

  it('error 非空时显示错误信息', () => {
    const error = new Error('网络异常')
    const wrapper = mount(AsyncState, {
      props: { loading: false, error, isEmpty: false },
    })

    expect(wrapper.find('[data-testid="error"]').exists()).toBe(true)
    expect(wrapper.find('[data-testid="error"]').text()).toContain('网络异常')
  })

  it('isEmpty=true 时显示空状态', () => {
    const wrapper = mount(AsyncState, {
      props: { loading: false, error: null, isEmpty: true },
    })

    expect(wrapper.find('[data-testid="empty"]').exists()).toBe(true)
  })

  it('点击 retry 触发 emit("retry")', async () => {
    const wrapper = mount(AsyncState, {
      props: { loading: false, error: new Error('x'), isEmpty: false },
    })

    await wrapper.find('[data-testid="retry-btn"]').trigger('click')

    expect(wrapper.emitted('retry')).toHaveLength(1)
  })
})
```

**要点**：

- `mount(component, options)` 创建完整组件实例
- `props` / `slots` / `global.stubs` 注入测试数据
- `wrapper.find(selector)` + `data-testid` 定位元素
- `wrapper.emitted(eventName)` 断言事件触发
- `await ...trigger('click')` 触发 DOM 事件

## 7. Mock 标准模式速查

| 场景                     | 标准用法                                                                      | 备注                           |
| ------------------------ | ----------------------------------------------------------------------------- | ------------------------------ |
| **mock 整个模块**        | `vi.mock('@api/http', () => ({ request: vi.fn() }))`                          | 自动 hoist 到文件顶部          |
| **mock 部分 + 保留其他** | `vi.mock('@vv/shared', async (importOriginal) => { ... })`                    | 用 `importOriginal` 拿真实导出 |
| **mock 函数返回值**      | `mockFn.mockResolvedValue(x)` / `mockRejectedValue(e)` / `mockReturnValue(x)` | resolve/reject 用于 Promise    |
| **mock Pinia store**     | `beforeEach(() => setActivePinia(createPinia()))`                             | 每个测试独立 pinia 实例        |
| **mock vue-router**      | `vi.mock('vue-router', () => ({ useRouter: () => ({ push: vi.fn() }) }))`     | 仅 stub 用到的 API             |
| **mock Element Plus**    | `mount(Component, { global: { stubs: { ElButton: true } } })`                 | 避免完整组件树挂载             |
| **mock axios / http.ts** | `vi.mock('@api/http')` + `vi.mocked(request).mockResolvedValue(...)`          | 配合 as never 绕过类型校验     |

**要点**：

- 所有 mock 在 `beforeEach` 里 `vi.clearAllMocks()` 重置计数
- 异步 mock 用 `mockResolvedValue` / `mockRejectedValue`（Promise 风格）
- 必要时用 `mockImplementation` 自定义返回值逻辑

## 8. 异步与时间

### 8.1 异步等待

```ts
// 替代 nextTick（用于 composable）
await vi.dynamicImportSettled()

// 替代 setTimeout
await new Promise((resolve) => setTimeout(resolve, 0))

// 等待 N 次事件循环
await flushPromises()
```

### 8.2 假定时器

```ts
beforeEach(() => {
  vi.useFakeTimers()
})

afterEach(() => {
  vi.useRealTimers()
})

it('debounce 500ms 后才触发', async () => {
  const fn = vi.fn()
  const debounced = debounce(fn, 500)

  debounced()
  vi.advanceTimersByTime(100)
  expect(fn).not.toHaveBeenCalled()

  vi.advanceTimersByTime(400)
  expect(fn).toHaveBeenCalledOnce()
})
```

## 11. 常见坑

| 症状                               | 原因                    | 解法                                                                                                                                                                          |
| ---------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wrapper.find(...)` 返回 undefined | 选择器写错或元素未渲染  | 用 `data-testid` 而非 class；先 `wrapper.html()` 看 DOM                                                                                                                       |
| `vi.mock` 不生效                   | import 在 mock 声明之前 | mock 必须在 import 之前（或用 `vi.hoisted`）                                                                                                                                  |
| `setActivePinia` 报错              | 测试未初始化 pinia      | `beforeEach(() => setActivePinia(createPinia()))`                                                                                                                             |
| `await flushPromises` 不工作       | 异步链路未完成          | 加 `await new Promise(r => setTimeout(r, 0))` 强制让出                                                                                                                        |
| Element Plus 组件挂载报错          | 依赖未 inline           | 工厂 `createVitestConfig` 已统一 inline `['element-plus', '@element-plus/icons-vue']`（`packages/config/src/create-vitest-config.ts`）；新增同类依赖走该单点，各 app 不再自配 |
| `useFakeTimers` 后异步不推进       | setTimeout 被冻结       | `vi.advanceTimersByTime(ms)` 主动推进                                                                                                                                         |

## 9. a11y 测试策略（组件级，/autoplan Phase 2 D-RA-1）

项目用 `vitest-axe` 做无障碍守卫，但**刻意不全量铺开**（全仓近 200 个组件 × jsdom 环境噪音，收益成本不成比例）。当前仅 2 个 spec 覆盖。判定规则：

- **要写 axe 用例**：公共交互组件，且键盘可达性 / ARIA 语义是它的对外契约（如 SidebarResizer 的拖拽手柄）
- **可跳过**：纯展示组件（无交互语义）、键盘交互已用事件序列用例覆盖的
- **写法参照**：`packages/ui/src/components/form-schema/composables/array-row-reaction.spec.ts` 与 `packages/ui/src/components/ProTable/ProTable.integration.spec.ts` 的现有用例

新组件 review 时按上表判断，不需要也不应为每个组件机械加 axe。
