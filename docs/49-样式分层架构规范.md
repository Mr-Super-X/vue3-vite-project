# 样式分层架构规范（docs/49）

> 五层样式分层 + monorepo 物理映射 + BEM 隔离纪律。
> 审计依据：`.claude/agent-reports/2026-11-02-样式分层架构审计.md`（2026-11-02 三 agent 全仓普查 + 交叉验证，含 2026-11-03 勘误注记）、`.claude/agent-reports/2026-11-03-样式分层规则符合度审计.md`（六条理想模型对照 + 裸值普查 + 暗色漂移链修复）。
> BEM 编写细则（`createNamespace` / `$BEM_PREFIX` / 反模式表）见 CLAUDE.md §3，本文不重复。

## 1. 分层总览

```text
┌─ L5 组件样式        SFC <style> 块，BEM 命名空间隔离（禁 scoped）
├─ L4 业务公共样式     工具类（utilities/custom.scss .vv-*）+ UnoCSS（virtual:uno.css）
├─ L3 UI 库覆盖层      Element Plus / Vant 主题覆盖（三级形态，见 §4）
├─ L2 基础层          base/（reset.css + transition.scss + a11y.css）+ normalize.css
└─ L1 Tokens 层       tokens/（值定义）+ themes/（主题覆盖）：颜色/间距/字号/圆角/阴影/z-index/动效
```

**依赖方向只许从上往下**（组件引用 tokens/mixin）；禁止基础层反向引用业务样式。

monorepo 物理映射（与传统单应用 `src/styles/` 目录对照；2026-11-03 起五目录骨架化）：

| 规范层          | 本仓物理位置                                                                           |
| --------------- | -------------------------------------------------------------------------------------- |
| 入口 index.scss | `packages/ui/src/styles/index.scss`（七段顺序头注即契约）                              |
| L1 tokens       | 同目录 `tokens/`（_colors/_spacing/_typography/_shadow/_z-index/_motion + index.scss） |
| L1 主题覆盖     | 同目录 `themes/`（_light/_dark mixin + index.scss 选择器应用点）                       |
| L2 base         | 同目录 `base/`（reset.css + transition.scss + a11y.css）+ npm `normalize.css`          |
| L3 UI 库覆盖    | 同目录 `element-overwrite/`（全局变量级）+ 组件/布局级（见 §4）                        |
| L4 工具类       | 同目录 `utilities/custom.scss`（`.vv-*`）+ UnoCSS                                      |
| L5 组件样式     | 各 SFC `<style lang="scss">`（非 scoped，BEM 隔离）                                    |
| tools（不入层） | 同目录 `tools/`（_bem/_responsive/_transitions，纯 mixin 零 CSS 产出，SFC 按需 @use）  |
| 端级样式层      | `apps/<a>/src/styles/`（6 端标配骨架：index/tokens/ui-overwrite，见 §5）               |

## 2. 加载顺序与入口（强约束）

1. **唯一入口**：各 app `main.ts` 只写 `import '@vv/ui/app-styles'`（四件套顺序：`normalize.css` → `virtual:uno.css` → `@vv/ui/styles/index.scss` → `element-plus/theme-chalk/dark/css-vars.css`）。禁止在 app 里另起全局样式 import 绕过该入口。
2. **index.scss 七段顺序**（后加载可覆盖先加载，新增文件按头注规则插入）：`base/reset.css` → `tokens/` → `themes/` → `base/transition.scss` → `base/a11y.css` → `element-overwrite/` → `utilities/custom.scss`。
3. **端级全局样式**（§5 的 `apps/<a>/src/styles/`）在 main.ts 中**紧跟 app-styles 之后** import，获得对公共层的覆盖权。
4. mixin 工具不进任何入口（SCSS module 不允许重复 @use 产出），SFC 内按需 `@use '@vv/ui/styles/tools/xxx'`；`bem` mixin 由 vite `additionalData` 全量预注入（`packages/config/src/scss.ts`），无须手写。

**入口例外**：无。6 端 main.ts 均为「`@vv/ui/app-styles` → `@/styles/index.scss`」两行同构；vant 主题覆盖已归位 `apps/h5/src/styles/ui-overwrite.scss`（2026-11-02 自 `layouts/h5/styles/vant-vars.scss` 迁入，`:root:root` 双写技巧原样保留）。

## 3. Design Tokens（L1）

### 3.1 双层变量设计

- **SCSS 变量 `$color-*`**：编译期常量，供 mixin 计算（如灯色阶 `color.mix`）。
- **CSS 变量 `--*`**：运行时变量，组件经 `var()` 消费，主题切换时跟随。

### 3.2 与 Element Plus 的关系（源/镜像立场，2026-11-02 裁决；2026-11-03 勘误）

- 项目 `$color-*` SCSS 常量为**编译期源**（`tokens/_colors.scss`）；`element-overwrite/theme-vars.scss` 将其镜像写入 `--el-color-*`（含 light-3/5/7/8/9 灯色阶，`color.mix` 算法与 EP theme-chalk 内部一致）。
- **消费纪律**：业务代码一律消费 `var(--el-*)` 或项目语义变量（`--color-*`/`--bg-*`/`--text-*`），**禁止写死色值**（新增色值先进 tokens）。
- 暗色双轨（2026-11-03 接线为真，此前为注释虚假声称）：`data-theme` 属性（驱动 `themes/` 业务变量）+ `html.dark` class（驱动 EP 官方 `dark/css-vars` 组件变量），由 theme store `applyTheme` 同步维护——`dark/css-vars` 经 app-styles 第四件全端引入；admin default 布局的手写暗色 mixin（`[data-theme='dark'][data-layout='default']`）双属性选择器优先级更高，作为品牌定制层保留。
- 品牌色运行时联动（2026-11-03 修复）：`injectBrandColor` 启动时同步注入 `--color-primary` 与 `--el-color-primary`（此前只设前者，EP 组件不跟随；灯色阶仍为编译期字面量不联动，局限已写入函数 JSDoc）。

### 3.3 命名与前缀

| 前缀                                                  | 归属                         | 实例                                                           |
| ----------------------------------------------------- | ---------------------------- | -------------------------------------------------------------- |
| 裸前缀 `--color-*` / `--spacing-*` / `--z-index-*` 等 | 全局（packages/ui 统一定义） | `--color-primary`、`--z-index-modal`                           |
| `--<app>-*` 端级前缀                                  | 各 app 私有 tokens           | `--portal-ink`、`--big-primary`、`--h5-text`、`--login-accent` |

新增端级 token 必须带端前缀，杜绝跨 app 撞名。

### 3.4 z-index 分层（强约束）

- 全局层级一律消费 `tokens/_z-index.scss` 的 `--z-index-*` token（dropdown 1000 → debug-banner 9999，含 banner 1999 / fullscreen 1500 / layout-overlay 4000 语义位）。
- 组件/布局内部叠放用 **1-100 自管**（如 admin 布局内部阶梯 5/10/20/25/30）。
- **禁止随手写数字**：新增全局层级先在 `tokens/_z-index.scss` 增补 token 并注释语义（2026-11-03 裸值复扫 >100 硬编码 0 违规）。

### 3.5 间距与尺寸

间距用 4 的倍数（`--spacing-xs/sm/md/lg/xl` = 4/8/16/24/32），对齐 EP size 体系（small/default/large）。

## 4. UI 库覆盖三级形态（EP 为主，Vant 同构）

| 级         | 位置                                                  | 适用场景                               | 实例                                                   |
| ---------- | ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------------ |
| 全局变量级 | `packages/ui/src/styles/element-overwrite/`           | 全局主色/灯色阶变量                    | `theme-vars.scss`                                      |
| 端级       | `apps/<a>/src/styles/ui-overwrite.scss`（标配骨架位） | 某端整体换肤/UI 库变量                 | h5 `src/styles/ui-overwrite.scss`（vant 变量覆盖）     |
| 布局级     | `apps/<a>/src/layouts/<l>/styles/`                    | 单布局品牌主题 + teleport 弹层变量映射 | admin `default-tokens.scss` + `element-overwrite.scss` |

**纪律**：

1. 优先覆盖 CSS 变量；必须写选择器时，权重控制在「BEM 根/容器类 + EP 类」两级，禁止 `!important`（CLAUDE.md §4 #13；a11y 降级场景除外）。
2. 全局覆盖一组件一文件，文件头注释写明「覆盖了什么、为什么」。
3. 布局级品牌主题的推荐写法（admin 范本）：EP 变量覆盖写成 `@mixin`，由布局容器类（如 `.vv-default-layout`）施加而非 `:root` 全局污染；teleport 弹层用 `[data-layout='...']` 属性选择器补齐——同页多布局并存时互不影响。

## 5. app 特性样式归属（两级归属 + 就近原则，2026-11-02 裁决并物理落地）

```text
apps/<a>/src/styles/                 # 端级（标配骨架）：6 端均已建，main.ts 统一接线
  ├── index.scss                     #   入口：@use tokens + ui-overwrite（全端同构）
  ├── tokens.scss                    #   端级 :root 变量位（--<app>-* 前缀，骨架含约定头注）
  └── ui-overwrite.scss              #   端级 UI 库覆盖位（h5 已承载 vant 变量实例）
apps/<a>/src/layouts/<l>/styles/     # 布局级：随布局入口 @use（admin/portal/big/h5 现状保持）
apps/<a>/src/modules/<m>/styles/     # 模块级：随模块页面 @use（auth login.scss 现状保持）
```

**归属判定一句话**：变量的消费者在哪一层就放哪一层——只服务一个布局的 token 留布局级，只服务一个页面的留模块级，全端共享才上 `src/styles/`，全局共享才进 `packages/ui`。

- 加载顺序：公共（app-styles）→ 端级（main.ts 第二顺位）→ 布局/模块级（随组件 @use）→ 组件级（SFC）。后加载覆盖先加载。
- 骨架全注释零 CSS 产出，新增内容直接填；`pnpm new-app` 脚手架自带同构三件套（模板 `scripts/templates/app/src/styles/`，spec 清单断言锁定）。
- 布局级既有 tokens（portal/big/h5/admin default）按就近原则原位保留，不强制搬迁。
- **端级暗色覆盖**（2026-11-03 补齐）：portal-tokens.scss / h5-tokens.scss 已配 `[data-theme='dark']` + `prefers-color-scheme` 双主题覆盖（mixin 与选择器分离，同 `themes/` 形态）；big/auth login 为**恒深色设计**（大屏暗室场景 / 登录页固定深空蓝），token 不随主题切换，文件头注已声明豁免。

**端级/布局级样式是否拆五目录（2026-11-03 评估裁决：不拆）**：端级与布局级 tokens 单文件保持「light 变量组 → dark mixin → 选择器应用点」内聚形态（admin/portal/h5 三端同构，与全局 `themes/` 拆分语义等价）。拆分触发条件（任一命中再拆）：单文件 >200 行 / 出现第三主题（sepia、high-contrast 等）/ 端级出现自有 mixin 需求（全局 `tools/` 无法承接时）。理由：最大单文件 163 行远低于收益阈值；4/6 端端级 tokens.scss 为空骨架；tools/utilities 在端级无存在意义（BEM 全局注入、原子类 UnoCSS 承接）。

## 6. 组件样式（L5）豁免登记

BEM 强约束见 CLAUDE.md §3。以下为审计确认的合法例外，除此之外无豁免：

| 例外形态                        | 位置                                                                             | 理由                                              |
| ------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------- |
| `<style module>`（CSS Modules） | form-schema 调试三件套：XFormErrorToast / XFormErrorToastItem / XFormDebugBanner | 开发态调试 UI 与业务样式双向防污染（头注已声明）  |
| 页面级 EP 后代选择器定制        | 如 auth `login.scss` 的 `.vv-login .el-card`                                     | 页面级外观定制属 L5 语义，前提是 BEM 根选择器兜底 |
| demo 演示内的色值/覆盖          | apps/docs 的 _StyleOverride_ 类示例                                              | demo 的色值是被演示对象本身                       |
| a11y 降级 `!important`          | ProTable `styles/_a11y.scss:70-73`                                               | `prefers-reduced-motion` 抑制行业标准写法         |

## 7. 新增样式自检清单

1. 归属层判定过了吗（§5 就近原则）？新色值/层级先进 tokens 了吗（DESIGN.md 登记先行）？
2. 组件样式：非 scoped + `lang="scss"` + 单一 `bem` 实例 + kebab-case 名（CLAUDE.md §3.2）？
3. EP 覆盖：走变量了吗？必须选择器时权重两级以内、无 `!important`？
4. z-index：走 `--z-index-*` token 或 1-100 局部自管？
5. 端级 token 带了 `--<app>-*` 前缀？
6. 新全局文件插进 index.scss 的顺序符合七段契约？
7. BEM 类名全英文 kebab-case？数据驱动类名经映射层转换（反例：Wide.vue 中文类名 `&--高/中/低`，2026-11-03 已修复为映射形态）？
