# 国际化（i18n）使用规范

> **文档版本**：v1.0.0 | **最后更新**：2026-07-24
> **覆盖范围**：什么时候用 i18n / key 命名约定 / 占位符插值 / 复数处理 / 路由 titleKey 集成 / 动态语言包懒加载
> **适用读者**：第一次给页面加多语言的新人 + 需要扩展 i18n 能力的老成员
> **配套源码**：`src/locales/{zh-CN,en-US,index}.ts` + `vue-i18n@^11.4.6`

---

## 1. 决策表：什么时候用 i18n

| 场景                                      | 用 i18n | 硬编码中文 | 备注                                       |
| ----------------------------------------- | ------- | ---------- | ------------------------------------------ |
| 用户可见的所有文字（标题/按钮/提示/菜单） | ✅      | ❌         | 哪怕只支持 zh-CN 也要走 i18n，方便后续扩展 |
| 内部日志（console.warn/error）            | —       | ✅         | 不面向用户                                 |
| 注释 / 文档字符串                         | —       | ✅         | 代码维护者看                               |
| Element Plus 默认文案                     | —       | —          | 走 Element Plus 自带 i18n（详见 §10）      |
| mock 数据 / 测试 fixture                  | —       | ✅         | 测试数据可以硬编码                         |

## 2. 文件结构

```
src/locales/
├── index.ts          # createI18n 实例（注册 zh-CN + en-US）
├── zh-CN.ts          # 简体中文词条
└── en-US.ts          # 英文词条
```

**约定**：

- 一个 locale 一个文件（避免把所有语言塞一个文件）
- key 用 `dot.case` 分层（详见 §3）
- 缺翻译时降级到 zh-CN（不是显示 key 字符串）

## 3. key 命名约定（**强制**）

### 3.1 分层规则

```
<namespace>.<sub>.<specific>
```

| namespace      | 范围                             | 示例                                      |
| -------------- | -------------------------------- | ----------------------------------------- |
| `common.*`     | 全站通用                         | `common.save`、`common.cancel`            |
| `menu.*`       | 侧边栏菜单                       | `menu.user.list`、`menu.home`             |
| `route.*`      | 路由 title（可选，与 menu 分离） | `route.user.detail`                       |
| `<module>.*`   | 业务模块                         | `equipment.name`、`order.status.pending`  |
| `error.*`      | 错误提示                         | `error.network`、`error.401`              |
| `validation.*` | 表单校验                         | `validation.required`、`validation.email` |

**为什么用 `dot.case`**：

- IDE 插件（i18n-ally / vscode-i18n-intl）按层级显示
- 重命名模块时批量替换安全
- TS 类型推导友好

### 3.2 反例（禁止）

| 反例                          | 原因                     |
| ----------------------------- | ------------------------ |
| `userList`（flat）            | 难以分组；插件展示混乱   |
| `user_list`（snake_case）     | 与项目 camelCase 不一致  |
| `UserList`（PascalCase）      | 与 dot 分层不一致        |
| `page.userList.title`（混合） | 看起来像驼峰但又不完全是 |

## 4. 基础用法

### 4.1 在 setup / template 中使用

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>

<template>
  <el-button>{{ t('common.save') }}</el-button>
  <h1>{{ t('menu.home') }}</h1>
</template>
```

### 4.2 在 store / composable 中使用

```ts
import { useI18n } from 'vue-i18n'

export function useErrorMessage() {
  const { t } = useI18n()
  return {
    getNetworkError: () => t('error.network'),
    get401: () => t('error.401'),
  }
}
```

### 4.3 在路由 meta 中声明 titleKey

```ts
// src/modules/order/routes/index.ts
{
  path: 'list',
  name: 'OrderList',
  component: () => import('../views/List.vue'),
  meta: {
    titleKey: 'menu.order.list',   // ← i18n key
    title: '订单列表',             // ← 兜底（i18n 不可用时）
    icon: 'list',
    requiresAuth: true,
  },
}
```

视图层：

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
import { useRoute } from 'vue-router'

const { t } = useI18n()
const route = useRoute()
const title = computed(() => t(route.meta.titleKey ?? route.meta.title ?? ''))
useHead({ title }) // 或手动 document.title = title.value
</script>
```

> Sidebar/Header 已自动从 `route.meta.titleKey` 解析（详见 `src/layouts/default/components/Sidebar.vue`）。

## 5. 占位符插值

```ts
// 词条定义
{
  equipment: {
    placeholder: '请输入{name}',
    welcome: '{name}，欢迎回来',
  },
}
```

```vue
<!-- 使用 -->
<p>{{ t('equipment.welcome', { name: '张三' }) }}</p>
<!-- 输出："张三，欢迎回来" -->
```

**类型安全**：

```ts
// vue-i18n 提供 TS 重载检查占位符
t('equipment.welcome', { name: '张三' }) // ✅
t('equipment.welcome', { nickname: '张三' }) // ❌ TS 报错
```

## 6. 复数处理（pluralization）

**场景**：根据数字显示不同文案（"1 个用户" vs "3 个用户"）。

```ts
// 词条定义（用管道分隔）
{
  user: {
    count: '没有用户 | 1 个用户 | {count} 个用户',
  },
}
```

```ts
const { t } = useI18n()
t('user.count', 0) // → "没有用户"
t('user.count', 1) // → "1 个用户"
t('user.count', 3) // → "3 个用户"
```

**英文复数**：

```ts
{
  user: {
    count: 'no users | 1 user | {count} users',
  },
}
```

## 7. 路由切换 + 语言切换

### 7.1 切换 API

```vue
<script setup lang="ts">
import { useAppStore } from '@store/modules/app'
const appStore = useAppStore()

function switchLocale(locale: 'zh-CN' | 'en-US') {
  appStore.setLocale(locale)
  // app store 内部调用 i18n.global.locale.value = locale
}
</script>

<template>
  <el-radio-group :model-value="appStore.locale" @change="switchLocale">
    <el-radio-button value="zh-CN">简体中文</el-radio-button>
    <el-radio-button value="en-US">English</el-radio-button>
  </el-radio-group>
</template>
```

### 7.2 持久化

`src/store/modules/app.ts` 的 `locale` 字段已用 `pinia-plugin-persistedstate` 持久化（pick: locale），刷新页面保留用户选择。

### 7.3 动态加载（懒加载语言包）

> 项目当前默认全量打包 zh-CN + en-US。如需支持更多 locale 且控制 bundle，应改为动态 import。

```ts
// src/locales/index.ts（懒加载版示例）
export async function loadLocaleMessages(locale: string) {
  const messages = await import(`./${locale}.ts`)
  i18n.global.setLocaleMessage(locale, messages.default)
  return messages.default
}
```

```ts
// 在用户切换语言时按需加载
async function switchLocale(locale: string) {
  if (!i18n.global.availableLocales.includes(locale)) {
    await loadLocaleMessages(locale)
  }
  i18n.global.locale.value = locale
}
```

## 8. Element Plus 文案联动 + 缺失翻译降级

Element Plus 自带 i18n，需与项目 locale 联动。在 `App.vue` 顶层包 `<ElConfigProvider :locale="...">`：

```vue
<script setup lang="ts">
import en from 'element-plus/es/locale/lang/en'
import zhCn from 'element-plus/es/locale/lang/zh-cn'
const elementLocale = computed(() => (i18n.global.locale.value === 'en-US' ? en : zhCn))
</script>

<template>
  <ElConfigProvider :locale="elementLocale">
    <router-view />
  </ElConfigProvider>
</template>
```

**缺失翻译降级**：`fallbackLocale: 'zh-CN'`，缺翻译时不显示 key 字符串。开发期开 `missing` 警告：

```ts
const i18n = createI18n({
  locale: 'zh-CN',
  fallbackLocale: 'zh-CN',
  missing: (locale, key) => {
    if (import.meta.env.DEV) console.warn(`[i18n] 缺翻译: ${locale}::${key}`)
  },
})
```

## 12. 常见坑

| 症状                        | 原因                         | 解法                                                 |
| --------------------------- | ---------------------------- | ---------------------------------------------------- |
| 切语言后页面文案没刷新      | 不是响应式                   | `t()` 返回 ref，模板 `{{ }}` 自动响应                |
| `t('xx.yy')` 返回 'xx.yy'   | 缺翻译 + 未设 fallback       | `fallbackLocale: 'zh-CN'`                            |
| 路由菜单项不显示英文        | `meta.title` 而非 `titleKey` | 改用 `titleKey: 'menu.xxx.yyy'`                      |
| 复数形式全部显示第一条      | 词条未用管道                 | 词条用 `没有 \| 1 个 \| {count} 个` 三段式           |
| Element Plus 弹窗文案不切换 | ElConfigProvider 未绑定      | 在 App.vue 顶层包 `<ElConfigProvider :locale="...">` |
