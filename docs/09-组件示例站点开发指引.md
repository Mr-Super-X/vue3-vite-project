# 组件示例站点开发指引

> **dev-only 文档站**，对标 element-plus 官网。开发者新增一个 demo 只需写 1 个文件，无需触碰 routes / types / whitelist / check-routes / sidebar 任何配置。
>
> 完整实现位于 `src/modules/demo/`。生产构建时被整体 tree-shake，**零字节**进入 prod bundle。

---

## 1. 5 分钟快速开始

加一个新 demo **只需 1 步**：

```bash
# 在 examples/ 目录新建 PascalCase.vue（或 PascalCase/index.vue）
touch src/modules/demo/examples/MyButton.vue
```

**自动生效**：

| 链路                                                | 自动结果                                      |
| --------------------------------------------------- | --------------------------------------------- |
| `routes/index.ts` 用 `import.meta.glob` 扫到        | path: `/demo/my-button`，name: `DemoMyButton` |
| `DocLayout` 从 `router.getRoutes()` 收集            | sidebar 自动出现"MyButton"链接                |
| `whitelist.ts` 从 `routeNames` 吸收                 | `/demo/my-button` 匿名可访问                  |
| `check-routes.ts` `EXEMPT_PREFIXES = ['Demo']` 豁免 | CI 一致性校验通过                             |
| `extractApi` 从源文件解析                           | API 表格自动填 name/type/required             |
| `vite.config.ts` 的 unocss 排除 demo 目录           | demo 不参与原子化 CSS 扫描                    |

**然后**启动 `pnpm dev:local`，浏览器访问 `http://localhost:5173/demo`，**首个 demo 自动打开**（按文件名字母序），点击 sidebar 切换其他 demo。

## 3. 完整模板

参考 `examples/AsyncState.vue`，**最小可运行的 demo 模板**：

```vue
<script setup lang="ts">
/**
 * 演示 + API 文档（半自动版）
 *
 * - name / type / required → 走 extractApi 自动从源码提取
 * - description → 手写字典（TS 类型里没 doc，强行自动会"乱猜"）
 */
import { ref } from 'vue'
import MyComponent from '@/components/common/MyComponent.vue' // 被演示的组件
import myComponentSource from '@/components/common/MyComponent.vue?raw'
import DemoFrame from '../components/DemoFrame.vue'
import DemoField from '../components/DemoField.vue'
import DocLayout from '../layouts/DocLayout.vue'
import ApiTable from '../components/ApiTable.vue'
import DocToc from '../components/DocToc.vue'
import { extractApi, type ApiItem, type SlotItem } from '../utils/extractApi'

// —— 演示逻辑（按需） ——
const state = ref(/* ... */)

// —— API 自动提取 + description 字典 merge ——
const api = extractApi(myComponentSource)

const propDescriptions: Record<string, string> = {
  prop1: '说明 1',
  prop2: '说明 2',
}

const eventDescriptions: Record<string, string> = {
  change: '说明',
}

const slotDescriptions: Record<string, string> = {
  default: '说明',
}

function merge<T extends { name: string }>(items: T[], descMap: Record<string, string>) {
  return items.map((it) => ({ ...it, description: descMap[it.name] ?? '—' }))
}

const propsItems = merge<ApiItem>(api.props, propDescriptions)
const eventsItems = merge<ApiItem>(api.events, eventDescriptions)
const slotsItems = merge<SlotItem & { type: string; default: string; required: boolean }>(
  api.slots.map((s) => ({
    ...s,
    type: s.scoped ? '作用域插槽' : '—',
    default: '—',
    required: false,
  })),
  slotDescriptions
)

const tocItems = [
  { id: 'demo-basic', label: '基础用法' },
  { id: 'api-props', label: 'Props' },
  { id: 'api-events', label: 'Events' },
  { id: 'api-slots', label: 'Slots' },
]
</script>

<template>
  <DocLayout>
    <DemoFrame
      title="MyComponent 组件名"
      source="src/components/common/MyComponent.vue"
      :introductions="['第一句说明', '第二句说明', '第三句使用提示']"
    >
      <section id="demo-basic">
        <DemoField :code="myComponentSource" label="被演示组件源码（MyComponent.vue）">
          <MyComponent v-bind="state" />
        </DemoField>
      </section>

      <ApiTable title="Props" :items="propsItems" anchor="api-props" />
      <ApiTable title="Events" :items="eventsItems" anchor="api-events" />
      <ApiTable title="Slots" :items="slotsItems" anchor="api-slots" />
    </DemoFrame>

    <template #toc>
      <DocToc :items="tocItems" />
    </template>
  </DocLayout>
</template>

<style lang="scss" scoped>
/* 演示页私有样式 */
</style>
```

**关键点**：

1. `extractApi(source)` 从源文件**自动**提取 name/type/required
2. `propDescriptions` 等**手写**中文 description 字典
3. `merge()` 把自动提取结果和手写 description 合并
4. `ApiTable` 内部 `v-if="items.length"`——**外部不要写 v-if**（避免切换时 sticky 布局抖动，见第 7 节）
5. `DocToc` items 顺序与 `ApiTable anchor` 顺序**一一对应**

## 4. 两种文件组织方式

`import.meta.glob` 同时扫两种形式：

| 形式                          | 适用场景                                          | 自动 path   | 自动 name      |
| ----------------------------- | ------------------------------------------------- | ----------- | -------------- |
| `examples/MyButton.vue`       | 简单单文件 demo                                   | `my-button` | `DemoMyButton` |
| `examples/MyButton/index.vue` | 需要附属文件（composables / 局部 store / 子组件） | `my-button` | `DemoMyButton` |

**派生逻辑**（`deriveComponentName` in `routes/index.ts`）：

- 文件末段是 `.vue` → 去掉后缀
- 文件末段是 `index.vue` → 取**父目录名**

## 5. API 文档自动化

`extractApi` 解析 .vue 源码：

| 字段            | 来源                                                       | 自动/手写               |
| --------------- | ---------------------------------------------------------- | ----------------------- |
| **name**        | `defineProps<{...}>()` / `defineEmits<{...}>()` / `<slot>` | ✅ 自动                 |
| **type**        | TS Compiler API 解析                                       | ✅ 自动                 |
| **required**    | `?:` 标记                                                  | ✅ 自动                 |
| **scoped**      | `<slot :foo="...">`                                        | ✅ 自动                 |
| **default**     | `withDefaults(defineProps<...>(), {...})`                  | ⚠️ 当前未实现（待 `—`） |
| **description** | —                                                          | 📝 手写 map             |

**支持解析**：

- `interface Props { name: type; name?: type }` 类型别名
- `defineEmits<{ event: [] }>()` / `defineEmits<{ event: [value: string] }>()` tuple 签名
- `<slot name="..." />` / `<slot>...</slot>` / `<slot />` 三种 slot 形式
- 嵌套 `<template v-if>` 内的 slot（**不**会被外层 template 截断——`extractSlots` 直接扫整个 source）

**不支持**：

- `withDefaults` 的 default value 提取（需要更复杂的 AST 分析）
- `defineProps({ ... })` 运行时声明形式（项目统一用 TS 类型，不支持）
- JSDoc 自动提取 description（TS 类型没 doc，强行自动会"乱猜"）

## 6. 命名约束

| 位置             | 约束                       | 例子                                  |
| ---------------- | -------------------------- | ------------------------------------- |
| 文件名           | **PascalCase**             | `MyButton.vue` ✅ / `myButton.vue` ❌ |
| 路由 name        | `Demo` + 文件名 PascalCase | `DemoMyButton`                        |
| 路由 path        | 文件名 kebab-case          | `my-button`                           |
| meta.title       | 文件名 PascalCase          | `MyButton`                            |
| 路由 `id` (锚点) | 组件自由                   | `demo-basic` / `api-props`            |

**路径转换**由 `src/utils/caseConvert.ts` 处理（`pascalCase` / `kebabCase`），所有路由转换都走这两个工具，**不在 demo 内手写**。

## 7. 常见踩坑

### 7.1 `vue/no-mutating-props` 误报

**症状**：ESLint 报 `Unexpected mutation of "Xxx" prop`。

**根因**：父组件 ref 与子组件 prop **同名**——ESLint 规则按字符串匹配，无法区分**修改父 ref** vs **修改子 prop**。

**修复**：**父 ref 改用不同名字**（子组件 prop 名是**被演示组件的 API**，不要动）：

```ts
// ❌ 父 ref 与子 prop 同名 → ESLint 误报
const shouldThrow = ref(false)
const Child = defineComponent({ props: { shouldThrow: Boolean } })

// ✅ 父 ref 改名为 errorTrigger
const errorTrigger = ref(false)
const Child = defineComponent({ props: { shouldThrow: Boolean } }) // prop 名不变
```

### 7.2 切换路由时布局抖动

**症状**：从 AsyncState 切到 ErrorBoundary，sidebar/toc 位置突变。

**根因**：`<ApiTable v-if="eventItems.length">` **外层** v-if 在路由切换时 unmount/mount，`sticky` 定位的 sidebar/toc 重新计算位置。

**修复**：把 v-if 移到 `ApiTable` **内部**：

```vue
<!-- ❌ 外部 v-if 导致布局抖动 -->
<ApiTable v-if="items.length" :items="items" />

<!-- ✅ ApiTable 内部判断空数组不渲染（外部稳定） -->
<ApiTable :items="items" />
```

`ApiTable.vue` 内部已用 `<section v-if="items.length">`，**外部不要再写 v-if**。

### 7.3 unocss 报错 `__uno.css:19` setTimeout 递归

**症状**：dev server 白屏，console 报 `RangeError: Maximum call stack size exceeded`。

**根因**：unocss 66.7.5 与 Vite 8 在某些 HMR 场景下的已知 bug。

**已规避**：`uno.config.ts` 已加 `exclude: [/src\/modules\/demo\/.*/]`——demo 模块不参与 unocss 扫描（demo 用 BEM 命名，**不依赖**原子化类）。**不要删除这行**。

## 8. 生产 tree-shake 验证

demo 模块是 dev-only，生产构建时**必须**完全剔除。验证方式：

```bash
pnpm build
echo "=== prod 中 demo 字符串残留 ==="
grep -oE '"Demo[A-Za-z]*"|doc-layout|api-table|doc-toc' dist/assets/*.js 2>/dev/null | sort -u
# 期望：空（完全剔除）
```

**当前实测**：✅ 0 残留。

**自动机制**：

- `routes/index.ts` 整个 `import.meta.env.DEV` 守卫——prod 替换为 `[]`
- `import.meta.glob` 同样 DEV 守卫——prod 不展开 examples 文件
- Rollup tree-shake 把整个 demo 模块 + 所有 examples 文件链剔除

## 9. 进阶：description 字典写哪里

三种选择，按推荐度排序：

| 位置                       | 推荐   | 适用                         |
| -------------------------- | ------ | ---------------------------- |
| **demo 文件 setup 内**     | ⭐⭐⭐ | 单一 demo 维护自己           |
| `utils/descriptionMaps.ts` | ⭐⭐   | 多个 demo 共享相同组件的描述 |
| JSDoc 注释在源码中         | ⭐     | 需要额外 `extractApi` 支持   |

**当前约定**：description 写在 demo 文件 setup 内（`propDescriptions` 等字典）。简单直接，无需跨文件查找。
