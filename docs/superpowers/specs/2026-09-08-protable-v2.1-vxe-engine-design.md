## 一、TL;DR

解除 `resolveEngine` 的 vxe 回退，让 `table-engine="vxe-table"` 真正渲染 vxe-table 引擎：

1. 恢复 `useVxeTable.ts` 骨架（git 历史 `aaedabf`），增强为「加载 + 安装 + CSS 注入」
2. 把 ProTable.vue 的 ElTable 渲染分支抽离为 `ElementTableBody.vue`（当前 430 行已超 300 行上限，直接加分支会到 ~550 行）
3. 新增 `VxeTableBody.vue` + `adapters/vxe-column.ts`（ProColumn → VxeColumn 映射）
4. 事件桥接对齐 M2 服务端排序 / 行编辑 / 多选
5. 能力矩阵：rowEdit / cellSpan 支持，tree / rowDrag 不支持（warn）

## 二、目标 & 非目标

### 2.1 目标

- `table-engine="vxe-table"` 端到端可用：加载 → 渲染 → 事件 → 服务端排序 → expose
- 存量 element-plus 行为零变化（抽离为纯移动，单独 refactor commit 验证）
- vxe 组件按需加载：不进首屏 bundle（dynamic import + CSS 动态注入）
- 4 类 v2 能力在 vxe 引擎的支持度显式化（validateCapabilities warn，不静默降级）

### 2.2 非目标

- vxe 引擎上的树形 / 行拖拽（数据模型与 DOM 结构差异大， warn 明确不支持）
- vxe Grid / Toolbar 高级封装（仅基础 Table + Column）
- 列设置抽屉 / 搜索表单在 vxe 下的差异化（复用现有组件，与引擎无关）
- element-plus 与 vxe 的样式主题统一

## 三、关键决策

### 决策 1：渲染分支抽离（必要，非过度设计）

ProTable.vue 现 430 行（编排 + ElTable 模板 + 事件桥接），业务组件上限 300 行（+30 上浮也不够）。直接塞 vxe 分支 ~550 行，违反 CLAUDE.md §一 #6。

```
ProTable.vue（编排层，缩回 ~280 行：props/emits/composables 接线/slots 转发/expose）
├── components/ElementTableBody.vue  # ElTable 分支整体搬迁（含列循环/编辑/树形/合并/拖拽手柄模板）
└── components/VxeTableBody.vue      # vxe-table 分支（新增，≤150 行）
```

两分支组件的 props 接口相同（data / columns / 能力状态 + 事件回调），ProTable.vue 按 `engineRef` v-if 选择。子组件为展示层，接 props + emit，不直接调 composables。

### 决策 2：vxe 加载与安装（沿用骨架语义增强）

骨架已有 dynamic import + module 缓存 + reset。增强两点：

- **CSS 动态注入**：`loadVxeTable()` 内 `await import('vxe-table/lib/style.css')`（vite 支持 CSS dynamic import，不污染首屏）
- **应用级安装**：vxe-table v4 组件需 `app.use(VxeUITable)` 注册（含内置组件如 VxeCheckbox）。在 `useVxeTable` 内通过 `getCurrentInstance().appContext.app` 拿到 app 安装，模块缓存保证只装一次

import 失败兜底保持骨架语义：catch 后回退 element-plus + warn（CONTRIBUTING 清单 #1）。

### 决策 3：列映射（adapters/vxe-column.ts）

vxe-table v4 列 API 与 element-plus 差异：

| ProColumn | VxeColumn | 说明 |
|---|---|---|
| `prop` | `field` | |
| `label` | `title` | |
| `width` / `minWidth` | 同名 | |
| `fixed` | 同名（`'left'/'right'`） | |
| `sortable: 'custom'` | `sortable: true` + 表级 `:sort-config="{ remote: true, ... }"` | 服务端排序（M2 状态复用） |
| `type: 'selection'` | `type: 'checkbox'` | |
| `enum` / `render` | default slot 渲染（复用 `resolveCell` 逻辑，提到共享处） | |
| `headerRender` | header slot | |
| `vxeProps` | 整体透传 | types 恢复该字段（清单 #3） |

### 决策 4：事件桥接（复用既有 handler，不新建状态）

| vxe 事件 | 桥接到 | 说明 |
|---|---|---|
| `@sort-change` | `handleSortChange`（列查 `sortable==='custom'`） | vxe 单排序事件，与 el-table 同签名核心字段 `{ field, order }`，适配后走 M2 同一通路 |
| `@checkbox-change` + `@checkbox-all` | `handleSelectionChange` | vxe 无合并的 selection-change，需两处合并（全选 + 单选） |
| `@cell-dblclick` | `handleCellDblClick` | 行编辑进入 |
| 树形 / 展开 | 不桥接 | tree 能力不支持（决策 5） |

### 决策 5：能力矩阵（validateCapabilities）

| 能力 | vxe 支持度 | 处理 |
|---|---|---|
| 行编辑 rowEdit | ✅ 支持 | cell-dblclick + EditCell 渲染复用 |
| 单元格合并 cellSpan | ✅ 支持 | vxe `span-method` + `cell-class-name` 映射 |
| 行拖拽 rowDrag | ❌ 不支持 | `getTbody` 选择器硬编码 `.el-table__body tbody`，vxe DOM 结构不同 → warn |
| 树形 tree | ❌ 不支持 | treeData 扁平化模型与 vxe tree-config 不同 → warn（清单 #7 已预告） |

warn 时机：setup 阶段 `useTableCapabilities` / `validateCapabilities` 检出即 warn（与 H3 死路径同一模式：warn + 忽略该能力，不白屏）。

### 决策 6：ProTableExpose.element

`tableRef` 类型为 el-table 实例；vxe 引擎下为 vxe-table 实例。类型上二者无公共接口，expose 保持 `unknown` 语义 + 注释说明「引擎相关，调用方自行断言」。JSDoc 同步（清单 #2）。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 抽离 ElementTableBody 时模板行为漂移 | 单独 refactor commit，移动前后跑全量测试 + demo 手动对比 |
| vxe `app.use` 与 unplugin-vue-components 冲突 | vxe 组件不走 auto-import，加载后手动安装；集成测试验证 |
| vxe TS 类型引用 `vxe-pc-ui`（未安装） | 不 import vxe 类型（沿用骨架「仅声明用到的部分」策略）；若 skipLibCheck 仍报错，加 `declare module 'vxe-pc-ui'` shim（不动依赖） |
| 全选/单选两事件合并时序 | 集成测试覆盖：单选 / 全选 / 翻页后状态 |
| vxe sort-change payload 与 el-table 字段名差异 | vxe `{ field, order: 'asc'|'desc'|null }` → 适配为内部 `SortChangeEvent { prop, order }` 后走同一通路 |

1. `table-engine="vxe-table"` 渲染 vxe-table，功能闭环：数据 / 分页 / 服务端排序 / 行编辑 / 多选 / 单元格合并

5. demo 引擎对比页手动验证通过
6. `pnpm type-check:full` / `lint` / `check:routes` 全绿
