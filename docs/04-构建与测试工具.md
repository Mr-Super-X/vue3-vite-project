## ⚙️ 核心配置文件

### `vite.config.ts`

> 当前真实配置。`alias` 已抽取为 `SRC_DIR_ALIASES` 常量 + `resolveSrcDirAliases()` 函数；`manualChunks` 已重构为顶部 `vendorChunks` 配置数组 + 遍历模式（便于扩展 vendor 分组）。

```ts
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'
import vueDevTools from 'vite-plugin-vue-devtools'
import UnoCSS from 'unocss/vite'
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'
import { viteMockServe } from 'vite-plugin-mock'
import { visualizer } from 'rollup-plugin-visualizer'

// src 下子目录别名映射（与 tsconfig.app.json paths 配置保持同步）
const SRC_DIR_ALIASES = {
  '@': '',
  '@api': 'api',
  '@assets': 'assets',
  '@components': 'components',
  '@composables': 'composables',
  '@directives': 'directives',
  '@enums': 'enums',
  '@layouts': 'layouts',
  '@locales': 'locales',
  '@modules': 'modules',
  '@plugins': 'plugins',
  '@router': 'router',
  '@store': 'store',
  '@types': 'types',
  '@utils': 'utils',
} as const

function resolveSrcDirAliases(): Record<string, string> {
  const map: Record<string, string> = {}
  for (const [alias, sub] of Object.entries(SRC_DIR_ALIASES)) {
    map[alias] = fileURLToPath(new URL(`./src/${sub}`, import.meta.url))
  }
  return map
}

// vendor chunk 分组（顺序敏感——先匹配先返回）
const vendorChunks: ReadonlyArray<{ name: string; patterns: ReadonlyArray<string> }> = [
  { name: 'vendor-vue', patterns: ['/vue/', '/pinia/', '/@vue/'] },
  { name: 'vendor-ui', patterns: ['/element-plus/', '/unplugin-vue-components/'] },
]

export default defineConfig({
  plugins: [
    vue(),
    vueJsx(),
    vueDevTools(),
    UnoCSS(),
    AutoImport({
      imports: ['vue', 'vue-router', 'pinia'],
      resolvers: [ElementPlusResolver()],
      dts: 'src/types/auto-imports.d.ts',
    }),
    Components({
      resolvers: [ElementPlusResolver()],
      dts: 'src/types/components.d.ts',
    }),
    viteMockServe({
      mockPath: 'mock',
      // 2026-07-27 切换：VITE_USE_MOCK 控制契约；dev 默认开启（未设时 !== 'false' 视为 true）
      enable: process.env.VITE_USE_MOCK !== 'false',
      watchFiles: true,
    }),
    ...(process.env.ANALYZE === 'true'
      ? [
          visualizer({
            filename: 'dist/stats.html',
            gzipSize: true,
            brotliSize: true,
            template: 'treemap',
          }),
        ]
      : []),
  ],
  resolve: { alias: resolveSrcDirAliases() },
  css: {
    preprocessorOptions: {
      // SCSS 'new-global' deprecation：Dart Sass 1.78+ 警告 "b() 内 !global 设新变量"
      scss: { silenceDeprecations: ['new-global'] },
      less: { javascriptEnabled: true },
    },
  },
  build: {
    target: 'es2022',
    sourcemap: false,
    chunkSizeWarningLimit: 1000,
    rollupOptions: {
      treeshake: true, // rolldown 推荐：移除未引用 export
      output: {
        manualChunks(id) {
          if (!id.includes('node_modules')) return undefined
          for (const { name, patterns } of vendorChunks) {
            if (patterns.some((p) => id.includes(p))) return name
          }
          return 'vendor-utils'
        },
      },
    },
  },
})
```

### 🆕 Vite 8 构建优化（别名 + Vendor Chunk）

#### 14 个子目录别名（告别相对路径）

| -------------- | --------------------- | ----------------------------- |

| `@components`  | `./src/components/*`  | 公共组件                      |
| `@composables` | `./src/composables/*` | 组合式函数（useRequest 等）   |
| `@directives`  | `./src/directives/*`  | 自定义指令（v-permission）    |
| `@enums`       | `./src/enums/*`       | 枚举常量                      |
| `@layouts`     | `./src/layouts/*`     | 页面布局                      |
| `@locales`     | `./src/locales/*`     | 国际化词条                    |
| `@modules`     | `./src/modules/*`     | 业务模块                      |
| `@router`      | `./src/router/*`      | 路由配置                      |
| `@store`       | `./src/store/*`       | Pinia store                   |
| `@types`       | `./src/types/*`       | 全局类型                      |

#### Vendor Chunk 拆分（利用浏览器强缓存）

**设计目标**：第三方库代码稳定 → chunk 文件名带 hash 不变 → 浏览器长期缓存；业务代码改动时只更新业务 chunk，第三方库 chunk 命中缓存。

**3 个 vendor chunk 分组**：

| Chunk          | 大小 (gzip)         | 内容                                                             |
| -------------- | ------------------- | ---------------------------------------------------------------- |
| `vendor-vue`   | 5.9 KB / 2.8 KB     | vue / vue-router / pinia / @vue/*                                |
| `vendor-ui`    | 477.8 KB / 167.3 KB | element-plus / @element-plus/icons-vue / unplugin-vue-components |
| `vendor-utils` | 123.9 KB / 43.5 KB  | axios / vue-i18n / 其他第三方                                    |

**为什么是函数式 manualChunks（不是对象）**：

Vite 8 用 **rolldown** 替代 rollup 作为底层打包器，API 变化：

| API            | Rollup (Vite 4-6)                    | Rolldown (Vite 8)                           |
| -------------- | ------------------------------------ | ------------------------------------------- |
| `manualChunks` | 支持对象 `{ 'vendor-vue': ['vue'] }` | **只支持函数** `function(id) { ... }`       |
| 错误信息       | 友好提示                             | `TypeError: manualChunks is not a function` |

**匹配逻辑**（基于 `id.includes()`，分组规则抽成配置数组，新增分组只需追加一项）：

```ts
// 配置：chunk 名 + 匹配模式列表（顺序敏感——先匹配先返回）
const vendorChunks: Array<{ name: string; patterns: string[] }> = [
  { name: 'vendor-vue', patterns: ['/vue/', '/pinia/', '/@vue/'] },
  { name: 'vendor-ui',  patterns: ['/element-plus/', '/unplugin-vue-components/'] },
]

manualChunks(id) {
  if (!id.includes('node_modules')) return undefined  // 业务代码不归 vendor
  for (const { name, patterns } of vendorChunks) {
    if (patterns.some(p => id.includes(p))) return name
  }
  return 'vendor-utils'  // 其他所有第三方
}
```

**缓存效益**：

| 场景              | 缓存策略                                                       |
| ----------------- | -------------------------------------------------------------- |
| 首次访问          | 下载所有 chunk（vendor-vue + vendor-ui + vendor-utils + 业务） |
| 升级 vue          | 只 `vendor-vue` hash 变，其他 vendor 命中缓存                  |
| 升级 element-plus | 只 `vendor-ui` hash 变                                         |
| 业务代码改动      | 只业务 chunk hash 变，3 个 vendor 全部缓存命中                 |
| 纯开发不升级      | 全部 304 Not Modified（极快）                                  |

**手动验证 3 种方法**（详见 `docs/01-工具兼容性问题踩坑记录.md`）：

```bash
# 方法 1: 浏览器 DevTools Network 标签（最直观）
pnpm dev
# F12 → Network → 刷新 → 筛选 JS chunk

# 方法 2: sourcemap 验证（最准确）
sed -i 's/sourcemap: false/sourcemap: true/' vite.config.ts
pnpm build
for f in dist/assets/vendor-*.js.map; do
  cat "$f" | grep -oE 'node_modules/[^"]+' | sort -u
done
sed -i 's/sourcemap: true/sourcemap: false/' vite.config.ts  # 还原

# 方法 3: 改源码对比 hash 变化（最直观感受缓存）
pnpm build 2>&1 | grep vendor  # 记录 hash
echo "--- 修改 src/App.vue 末尾加个空行 ---"
pnpm build 2>&1 | grep vendor  # 对比：业务 chunk 变 hash，vendor 不变
```

#### 包体积分析（rollup-plugin-visualizer）

**目的**：直观查看打包产物中各模块的体积占比，精准定位优化目标（如 `vendor-ui` 占了 477KB / 167KB gzip 太大时，可以排查是否引入了整个 `element-plus` 而不是按需引入）。

**配置**（vite.config.ts）：

```ts
import { visualizer } from 'rollup-plugin-visualizer'

// 在 plugins 数组里条件添加
...(process.env.ANALYZE === 'true'
  ? [
      visualizer({
        filename: 'dist/stats.html',
        gzipSize: true,        // 同时显示 gzip 压缩后大小
        brotliSize: true,      // 同时显示 brotli 压缩后大小
        template: 'treemap',    // 树状图（模块层级清晰）
      }),
    ]
  : []),
```

**为什么默认关闭（通过 `ANALYZE` env 变量启用）**：

- 视觉化生成耗时（build 时间 +200-500ms）
- 不想每次 build 都生成 `dist/stats.html`（仓库 diff 噪声）
- 想分析时手动启用

**package.json scripts**：

```json
"analyze": "ANALYZE=true pnpm build"
```

**使用方法**：

```bash
# 1. 跑分析（生成 dist/stats.html，~955 KB）
pnpm analyze

# 2. 浏览器打开
# Windows
start dist/stats.html
# macOS
open dist/stats.html
# Linux
xdg-open dist/stats.html
```

**生成的 `dist/stats.html` 含什么**：

| 维度           | 内容                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| **可视化样式** | 树状图（treemap），模块按层级嵌套                                             |
| **大小统计**   | 原始 / gzip / brotli 三种大小并列显示                                         |
| **模块分类**   | 按 `vendor-vue` / `vendor-ui` / `vendor-utils` 三大 vendor chunk 直观展示占比 |
| **依赖来源**   | 标出每个模块来自 `node_modules` 还是 `src/`                                   |
| **交互**       | 可点击进入子目录、悬停显示详细大小                                            |

**典型优化场景**：

| 现象                  | 优化方向                              |
| --------------------- | ------------------------------------- |
| `element-plus` 占大半 | 改用 unplugin-vue-components 按需引入 |
| `vue-i18n` 整个引入   | 改为按 locale 动态 import             |
| 业务 chunk 偏大       | 拆分子路由 / 动态 import              |
| `vendor-utils` 偏大   | 排查重复依赖（pnpm dedupe 检查）      |

**⚠️ 注意**：分析报告 `dist/stats.html` 已在 `.gitignore` 排除（无需入库）。

### `vitest.config.ts`

```ts
import { fileURLToPath } from 'node:url'
import { mergeConfig, defineConfig, configDefaults } from 'vitest/config'

export default mergeConfig(
  viteConfig as never,
  defineConfig({
    test: {
      environment: 'jsdom',

        },
      },
      css: true,
      coverage: {
        provider: 'v8',
        reporter: ['text', 'html', 'lcov'],
        include: ['src/**/*.{ts,vue}'],
        exclude: ['src/**/__tests__/**', 'src/**/index.ts', 'src/main.ts', 'src/types/**'],
```

**关键点**：

- `coverage`：v8 provider + 70% 阈值（脚手架阶段宽松）

## 🐛 故障排查

### 1. `pnpm dev` 启动报 `IGNORED_BUILDS`

**症状**：`Ignored build scripts: @parcel/watcher, esbuild`

**解决**：`pnpm-workspace.yaml` 加 allowBuilds：

```yaml
allowBuilds:
  '@parcel/watcher': true
  esbuild: true
```

### 2. Vitest 报 `Unknown file extension ".css"`

**原因**：vitest 默认不处理 CSS 导入

**解决**：`vitest.config.ts` 加 `css: true` + `server.deps.inline: ['element-plus']`

### 3. Vue Router 报 `No match found for location`

**原因**：路由 path 配置错误或 404 fallback 未配置

**解决**：检查 `src/router/modules/*.ts` 的 path 配置，并在最后加 catch-all：

```ts
{ path: '/:pathMatch(.*)*', redirect: '/404' }
```

### 4. Pinia store 跨模块引用报错

**原因**：违反模块边界铁律（modules 间不互相 import 内部）

**解决**：模块间通信通过 `modules/<m>/index.ts` 暴露的对外接口

### 5. `vue-tsc --build` 报 "Cannot find type definition file"

**解决**：检查 `tsconfig.app.json` 的 `types` 字段是否包含 `vite/client` 和 `node`
