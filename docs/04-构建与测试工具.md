## 🔄 构建工作流

```text
pnpm dev
   ↓
vite (dev server)
   ├── UnoCSS 插件（生成原子化 CSS）
   ├── AutoImport（自动导入 ref/computed 等）
   ├── Components（自动注册 Element Plus）
   ├── Mock（拦截 /api/* 请求）
   └── Vue/TS 热更新（HMR < 50ms）

pnpm build
   ↓
build-only (vite build) → dist/ → type-check:full (vue-tsc --force 全量门禁)
   ※ 顺序原因：CI 干净环境 unplugin 仅在 build 时生成 components.d.ts /
     auto-imports.d.ts，必须先 build 再 type-check，否则缺类型声明失败

pnpm test
   ↓
vitest run → jsdom 环境 → 25+ 测试用例
```

## ⚙️ 核心配置文件

### `vite.config.ts`（工厂消费形态，v3.0.0 起）

> 单应用时代的 `build/` 工程化目录已整体随迁为 `@vv/config` 包（v3.0.0 Monorepo 迁移，根 `build/` 删除）。各 app `vite.config.ts` 只剩工厂调用 + app 私有插件；插件装配 / AutoImport + Components 注入 / 别名 / css 预处理 / 构建分包的模块清单与职责见 §1.1，历史拆分设计见 `docs/superpowers/specs/2026-09-10-vite-config-split-design.md`。

**apps/admin/vite.config.ts 当前真实形态**（6 app 同构，仅 `h5Rem` 与 `extraPlugins` 等不同——P2 起 app 参数由 `app.manifest.json` 单源提供，不再由调用方传 `appName`/`portOffset`）：

```ts
import { fileURLToPath } from 'node:url'
import vueDevTools from 'vite-plugin-vue-devtools'
import { visualizer } from 'rollup-plugin-visualizer'
import { createViteConfig } from '@vv/config'

const appRoot = fileURLToPath(new URL('.', import.meta.url))

export default createViteConfig({
  appRoot,
  h5Rem: false, // h5 rem 适配归 apps/h5（postcss 转换范围锚定 appRoot）
  extraPlugins: [
    vueDevTools(),
    // 包体积分析（默认关闭，ANALYZE=true 启用）
    ...(process.env.ANALYZE === 'true'
      ? [visualizer({ filename: 'dist/stats.html' /* ... */ })]
      : []),
  ],
})
```

> 阅读源码时认准 `packages/config/src/create-vite-config.ts` 的 `createViteConfig`——所有 app 的 vite 行为都从这里派生。

### 构建产物分目录（js / css / img 各归其位）

> 此前 dist 全部平铺在单目录，运维排查与 CDN 差异化缓存不便。本次按资源类型分目录输出，commit `492b539` 已落地。

`@vv/config` 工厂（`packages/config/src/create-vite-config.ts`）的 `build.rollupOptions.output` 三处函数分流：

| 字段                        | 函数返回值              | 输出位置                                   | 典型示例                                      |
| --------------------------- | ----------------------- | ------------------------------------------ | --------------------------------------------- |
| `entryFileNames`            | `'js/[name]-[hash].js'` | `dist/js/`                                 | 入口 JS                                       |
| `chunkFileNames`            | `'js/[name]-[hash].js'` | `dist/js/`                                 | 代码分割 chunk（与入口同目录，统一 js/ 前缀） |
| `assetFileNames(assetInfo)` | 按扩展名分流            | `dist/css/` / `dist/img/` / `dist/assets/` | 详见下方分流规则                              |

**assetFileNames 分流规则**（命中优先级从高到低）：

| 扩展名（含 `.`）                                              | 输出子目录     | 备注                                                       |
| ------------------------------------------------------------- | -------------- | ---------------------------------------------------------- |
| `.css`                                                        | `dist/css/`    | 普通 CSS + Element Plus 主题覆盖                           |
| `.png .jpg .jpeg .gif .svg .webp .ico .bmp .avif .tiff .apng` | `dist/img/`    | 11 种常见图片格式                                          |
| 其它（`.woff2` / `.ttf` 等字体等）                            | `dist/assets/` | 兜底目录，本项目当前无字体产物，目录在有对应资源时按需生成 |

> 注：`assetInfo.name` 在 rolldown 类型中已 `@deprecated`，实现改用 `assetInfo.names` 数组（取首个原始文件名判定）。

**pnpm build 实测产物数**（commit `492b539` 验证记录）：

| 类型                                     | 产物数 | 输出目录    |
| ---------------------------------------- | ------ | ----------- |
| js（含入口 + chunk + vendor）            | 26     | `dist/js/`  |
| css（含 element-plus 主样式 + 主题覆盖） | 16     | `dist/css/` |
| 图片（svg / ico 等）                     | 10     | `dist/img/` |
| 根目录散落                               | 0      | —           |

`vite preview` 起本地服务：index.html 引用路径正确（`/js/*` `/css/*`），css 内 `url(/img/*)` 绝对路径无相对路径 404 风险。

**为什么需要分目录**：

- **运维排查**：CDN 上 `dist/js/` 单独设置长缓存（contenthash），`dist/css/` 短缓存或即时刷新（主题常迭代），`dist/img/` 可走图床加速
- **差异化缓存策略**：字体等 `dist/assets/` 不进 img/，避免被图床缓存规则误命中
- **保留 Vite 默认 hash**：contenthash 仍按文件内容计算，分目录不破坏缓存语义

### 🆕 Vite 8 构建优化（别名 + Vendor Chunk）

#### 14 个子目录别名（告别相对路径）

别名单一来源为 `packages/config/src/app-aliases.ts` 的 `createAppAliases(appRoot)`——vite `resolve.alias` 与各 app `tsconfig.app.json` 的 `paths` 由它生成，`pnpm check:aliases` 校验漂移（CI 阻断）：

| 别名                                             | 映射                                                     | 典型用途                          |
| ------------------------------------------------ | -------------------------------------------------------- | --------------------------------- |
| `@`                                              | `apps/<a>/src/*`                                         | app 私有根别名（恒指本 app src）  |
| `@api`                                           | `packages/shared/src/api/*`                              | 接口层（http / modules / 拦截器） |
| `@composables`                                   | `packages/shared/src/composables/*`                      | 组合式函数（useRequest 等）       |
| `@store`                                         | `packages/shared/src/store/*`                            | 全局 Pinia store                  |
| `@utils` / `@enums` / `@locales` / `@directives` | `packages/shared/src/{utils,enums,locales,directives}/*` | 共享工具 / 枚举 / 词条 / 指令     |
| `@components` / `@assets`                        | `packages/ui/src/{components,assets}/*`                  | 全局组件 / 图标等样式资产         |
| `@mock`                                          | `packages/mock/src/*`                                    | mock 数据源                       |
| `@modules` / `@layouts` / `@router` / `@plugins` | `apps/<a>/src/{modules,layouts,router,plugins}/*`        | app 私有目录                      |

**使用对比**：

```ts
// 之前（相对路径）
import { useUserStore } from '../../../store/modules/user'
import { formatDateOnly } from '../../../utils/format'

// 现在（Monorepo：全局 store / utils 已迁 @vv/shared 包，走包名 barrel 单点出口）
import { useUserStore, formatDateOnly } from '@vv/shared'

// app 私有文件仍用根别名（@/ 恒指本 app 的 src）
import MyPage from '@/modules/reports/views/MyPage.vue'
```

#### Vendor Chunk 拆分（利用浏览器强缓存）

**设计目标**：第三方库代码稳定 → chunk 文件名带 hash 不变 → 浏览器长期缓存；业务代码改动时只更新业务 chunk，第三方库 chunk 命中缓存。

**4 个 vendor chunk 分组**（v2.0 起，`vendor-charts` 为新增）：

| Chunk           | 大小 (gzip)         | 内容                                                                                |
| --------------- | ------------------- | ----------------------------------------------------------------------------------- |
| `vendor-vue`    | 5.9 KB / 2.8 KB     | vue / vue-router / pinia / @vue/*                                                   |
| `vendor-ui`     | 477.8 KB / 167.3 KB | element-plus / @element-plus/icons-vue / unplugin-vue-components                    |
| `vendor-charts` | ~1.1 MB / ~340 KB   | **echarts**（v2.0 新增独立打包，避免污染 vendor-ui 缓存命中）                       |
| `vendor-utils`  | 195 KB / ~70 KB     | axios / vue-i18n / 其他第三方（v2.0 起从 vendor-utils 剥离 echarts 后体积大幅缩小） |

**为什么是函数式 manualChunks（不是对象）**：

Vite 8 用 **rolldown** 替代 rollup 作为底层打包器，API 变化：

| API            | Rollup (Vite 4-6)                    | Rolldown (Vite 8)                           |
| -------------- | ------------------------------------ | ------------------------------------------- |
| `manualChunks` | 支持对象 `{ 'vendor-vue': ['vue'] }` | **只支持函数** `function(id) { ... }`       |
| 错误信息       | 友好提示                             | `TypeError: manualChunks is not a function` |

**匹配逻辑**（基于 `id.includes()`，分组规则抽成配置数组，新增分组只需追加一项）：

```ts
// 配置：chunk 名 + 匹配模式列表（顺序敏感——先匹配先返回）
const vendorChunks: Array<{ name: string; patterns: string[] }> = [
  { name: 'vendor-vue', patterns: ['/vue/', '/pinia/', '/@vue/'] },
  { name: 'vendor-ui',  patterns: ['/element-plus/', '/unplugin-vue-components/', '/vant/'] },
]

manualChunks(id) {
  if (!id.includes('node_modules')) return undefined  // 业务代码不归 vendor
  for (const { name, patterns } of vendorChunks) {
    if (patterns.some(p => id.includes(p))) return name
  }
  return 'vendor-utils'  // 其他所有第三方
}
```

**缓存效益**：

| 场景              | 缓存策略                                                       |
| ----------------- | -------------------------------------------------------------- |
| 首次访问          | 下载所有 chunk（vendor-vue + vendor-ui + vendor-utils + 业务） |
| 升级 vue          | 只 `vendor-vue` hash 变，其他 vendor 命中缓存                  |
| 升级 element-plus | 只 `vendor-ui` hash 变                                         |
| 业务代码改动      | 只业务 chunk hash 变，3 个 vendor 全部缓存命中                 |
| 纯开发不升级      | 全部 304 Not Modified（极快）                                  |

**手动验证 3 种方法**（详见 `docs/01-工具兼容性问题踩坑记录.md`）：

```bash
# 方法 1: 浏览器 DevTools Network 标签（最直观）
pnpm dev
# F12 → Network → 刷新 → 筛选 JS chunk

# 方法 2: sourcemap 验证（最准确）
sed -i 's/sourcemap: false/sourcemap: true/' vite.config.ts
pnpm build
for f in dist/assets/vendor-*.js.map; do
  cat "$f" | grep -oE 'node_modules/[^"]+' | sort -u
done
sed -i 's/sourcemap: true/sourcemap: false/' vite.config.ts  # 还原

# 方法 3: 改源码对比 hash 变化（最直观感受缓存）
pnpm build 2>&1 | grep vendor  # 记录 hash
echo "--- 修改 src/App.vue 末尾加个空行 ---"
pnpm build 2>&1 | grep vendor  # 对比：业务 chunk 变 hash，vendor 不变
```

#### 包体积分析（rollup-plugin-visualizer）

**目的**：直观查看打包产物中各模块的体积占比，精准定位优化目标（如 `vendor-ui` 占了 477KB / 167KB gzip 太大时，可以排查是否引入了整个 `element-plus` 而不是按需引入）。

**配置**（vite.config.ts）：

```ts
import { visualizer } from 'rollup-plugin-visualizer'

// 在 plugins 数组里条件添加
...(process.env.ANALYZE === 'true'
  ? [
      visualizer({
        filename: 'dist/stats.html',
        gzipSize: true,        // 同时显示 gzip 压缩后大小
        brotliSize: true,      // 同时显示 brotli 压缩后大小
        template: 'treemap',    // 树状图（模块层级清晰）
      }),
    ]
  : []),
```

**为什么默认关闭（通过 `ANALYZE` env 变量启用）**：

- 视觉化生成耗时（build 时间 +200-500ms）
- 不想每次 build 都生成 `dist/stats.html`（仓库 diff 噪声）
- 想分析时手动启用

**package.json scripts**：

```json
"analyze": "cross-env ANALYZE=true pnpm -C apps/admin build-only"
```

**使用方法**：

```bash
# 1. 跑分析（生成 dist/stats.html，~955 KB）
pnpm analyze

# 2. 浏览器打开
# Windows
start dist/stats.html
# macOS
open dist/stats.html
# Linux
xdg-open dist/stats.html
```

**生成的 `dist/stats.html` 含什么**：

| 维度           | 内容                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| **可视化样式** | 树状图（treemap），模块按层级嵌套                                             |
| **大小统计**   | 原始 / gzip / brotli 三种大小并列显示                                         |
| **模块分类**   | 按 `vendor-vue` / `vendor-ui` / `vendor-utils` 三大 vendor chunk 直观展示占比 |
| **依赖来源**   | 标出每个模块来自 `node_modules` 还是 `src/`                                   |
| **交互**       | 可点击进入子目录、悬停显示详细大小                                            |

**典型优化场景**：

| 现象                  | 优化方向                              |
| --------------------- | ------------------------------------- |
| `element-plus` 占大半 | 改用 unplugin-vue-components 按需引入 |
| `vue-i18n` 整个引入   | 改为按 locale 动态 import             |
| 业务 chunk 偏大       | 拆分子路由 / 动态 import              |
| `vendor-utils` 偏大   | 排查重复依赖（pnpm dedupe 检查）      |

**⚠️ 注意**：分析报告 `dist/stats.html` 已在 `.gitignore` 排除（无需入库）。

**strict 模式额外配置**：

| 选项                         | 作用                                      |
| ---------------------------- | ----------------------------------------- |
| `noUncheckedIndexedAccess`   | 数组/对象下标访问返回 `T \| undefined`    |
| `exactOptionalPropertyTypes` | 区分 `prop?: T` 和 `prop: T \| undefined` |
| `noImplicitOverride`         | 子类覆盖父类方法必须加 `override`         |

## 🐛 故障排查

### 1. `pnpm dev` 启动报 `IGNORED_BUILDS`

**症状**：`Ignored build scripts: @parcel/watcher, esbuild`

**解决**：`pnpm-workspace.yaml` 加 allowBuilds：

```yaml
allowBuilds:
  '@parcel/watcher': true
  esbuild: true
```

### 2. Vitest 报 `Unknown file extension ".css"`

**原因**：vitest 默认不处理 CSS 导入

**解决**：`vitest.config.ts` 加 `css: true` + `server.deps.inline: ['element-plus']`

### 3. Vue Router 报 `No match found for location`

**原因**：路由 path 配置错误或 404 fallback 未配置

**解决**：检查 `apps/<a>/src/modules/<m>/routes/` 的 path 配置（各 app 业务路由由 `apps/<a>/src/router/auto-register.ts` 自动扫描注册），并在最后加 catch-all：

```ts
{ path: '/:pathMatch(.*)*', redirect: '/404' }
```

### 4. Pinia store 跨模块引用报错

**原因**：违反模块边界铁律（modules 间不互相 import 内部）

**解决**：模块间通信通过 `modules/<m>/index.ts` 暴露的对外接口

### 5. `vue-tsc --build` 报 "Cannot find type definition file"

**解决**：检查 `tsconfig.app.json` 的 `types` 字段是否包含 `vite/client` 和 `node`
