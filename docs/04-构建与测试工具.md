**架构图**：

```text

└──────┬──────────┬──────────┬──────────┬──────────┬───────────┘
       │          │          │          │          │
```

**vite.config.ts 当前真实形态**（仅 plugin 装配 + 委派 build/*）：

```ts
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'
import vueDevTools from 'vite-plugin-vue-devtools'
import UnoCSS from 'unocss/vite'
import AutoImport from 'unplugin-auto-import/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'
import { viteMockServe } from 'vite-plugin-mock'
import { visualizer } from 'rollup-plugin-visualizer'
import { resolveSrcDirAliases, VENDOR_CHUNKS, SERVER_DEFAULTS, SCSS_OPTIONS } from './build'

export default defineConfig({
  plugins: [
    vue(),
    vueJsx(),
    vueDevTools(),
    UnoCSS(),
    AutoImport({
      imports: ['vue', 'vue-router', 'pinia'],
      // ... 业务 composables + utils 由 build/index.ts barrel 统一注入
      dts: 'src/types/auto-imports.d.ts',
    }),
    /* unplugin-vue-components 由 ElementPlusResolver 单独配置 */
    viteMockServe({
      mockPath: 'mock',
      enable: process.env.VITE_USE_MOCK !== 'false',
      watchFiles: true,
    }),
    ...(process.env.ANALYZE === 'true' ? [visualizer({/* ... */})] : []),
  ],
  resolve: { alias: resolveSrcDirAliases() },
  server: SERVER_DEFAULTS,
  css: { preprocessorOptions: SCSS_OPTIONS },
  build: {
    target: 'es2022',
    rollupOptions: {
      treeshake: true,
      output: {
        // VENDOR_CHUNKS 顺序敏感——先匹配先返回
        manualChunks(id) {
          if (!id.includes('node_modules')) return undefined
          for (const { name, patterns } of VENDOR_CHUNKS) {
            if (patterns.some((p) => id.includes(p))) return name
          }
          return 'vendor-utils'
        },
      },
    },
  },
})
```

### 1.1 build/ 工程化拆分（v2.0 新增）

`build/` 目录的 6 个模块把 vite.config.ts 的内联配置拆为语义化文件，**全部 spec 覆盖 + barrel 整合**：

| 模块                     | 职责                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| `build/aliases.ts`       | `SRC_DIR_ALIASES` 单一来源（15 个别名）+ `resolveSrcDirAliases()` 的 vite 侧 + tsconfig 侧双产物 |
| `build/vendor-chunks.ts` | `VENDOR_CHUNKS` 4 组配置（vendor-vue / vendor-ui / **vendor-charts** / vendor-utils），顺序敏感  |
| `build/scss.ts`          | `SCSS_OPTIONS` + `silenceDeprecations`（bem mixin 兼容 `new-global` deprecation）                |
| `build/server.ts`        | `SERVER_DEFAULTS`（port `5174` + `strictPort`）                                                  |
| `build/proxy.ts`         | `createProxyConfig(env)` 预留空壳（联调真实后端时启用）                                          |
| `build/index.ts`         | barrel re-export，vite.config.ts 一行 `import { ... } from './build'` 整合                       |

**关联脚本**：

| 脚本                                       | 触发                           | 作用                                                                                                           |
| ------------------------------------------ | ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `build/scripts/generate-tsconfig-paths.ts` | `pnpm generate:tsconfig-paths` | 读 `SRC_DIR_ALIASES` → 写入 `tsconfig.app.json` 的 `paths` 块；hash 比对无变更秒跳过；`--check` 模式供 CI 校验 |
| `scripts/check-aliases.ts`                 | `pnpm check:aliases`           | 对比 `SRC_DIR_ALIASES` 与 `tsconfig.app.json` 的 paths；漂移则 CI 失败                                         |
| `.husky/pre-commit`                        | commit 前自动                  | `pnpm generate:tsconfig-paths` 头 + `pnpm check:aliases` 尾 → 单一来源永远同步                                 |

**为什么单一来源**：

- 改动 `build/aliases.ts` 一处即可同步 vite + tsconfig 两侧（之前要改 vite.config.ts + tsconfig.app.json 两处且容易漂移）
- pre-commit 钩子保证 paths 永远一致，CI 阻断漂移提交
- 23 个 spec 用例覆盖：aliases (9) / vendor-chunks (4) / proxy (2) / server (2) / scss (3) / generate-tsconfig-paths (3)

**关键插件**（与 v1.0 保持一致）：

| 插件                       | 作用                                        |
| -------------------------- | ------------------------------------------- |
| `@vitejs/plugin-vue`       | Vue SFC 编译                                |
| `@vitejs/plugin-vue-jsx`   | JSX/TSX 支持                                |
| `vite-plugin-vue-devtools` | Vue DevTools 集成                           |
| `unocss/vite`              | 原子化 CSS                                  |
| `unplugin-auto-import`     | 自动导入（无需手动 import ref/computed 等） |
| `unplugin-vue-components`  | 自动注册组件（含 Element Plus）             |
| `vite-plugin-mock`         | 开发态 API Mock                             |

#### Vendor Chunk 拆分（利用浏览器强缓存）

**设计目标**：第三方库代码稳定 → chunk 文件名带 hash 不变 → 浏览器长期缓存；业务代码改动时只更新业务 chunk，第三方库 chunk 命中缓存。

**4 个 vendor chunk 分组**（v2.0 起，`vendor-charts` 为新增）：

| Chunk           | 大小 (gzip)         | 内容                                                                                |
| --------------- | ------------------- | ----------------------------------------------------------------------------------- |
| `vendor-vue`    | 5.9 KB / 2.8 KB     | vue / vue-router / pinia / @vue/*                                                   |
| `vendor-ui`     | 477.8 KB / 167.3 KB | element-plus / @element-plus/icons-vue / unplugin-vue-components                    |
| `vendor-charts` | ~1.1 MB / ~340 KB   | **echarts**（v2.0 新增独立打包，避免污染 vendor-ui 缓存命中）                       |
| `vendor-utils`  | 195 KB / ~70 KB     | axios / vue-i18n / 其他第三方（v2.0 起从 vendor-utils 剥离 echarts 后体积大幅缩小） |

**为什么是函数式 manualChunks（不是对象）**：

Vite 8 用 **rolldown** 替代 rollup 作为底层打包器，API 变化：

| API            | Rollup (Vite 4-6)                    | Rolldown (Vite 8)                           |
| -------------- | ------------------------------------ | ------------------------------------------- |
| `manualChunks` | 支持对象 `{ 'vendor-vue': ['vue'] }` | **只支持函数** `function(id) { ... }`       |
| 错误信息       | 友好提示                             | `TypeError: manualChunks is not a function` |

**匹配逻辑**（基于 `id.includes()`，分组规则抽成配置数组，新增分组只需追加一项）：

```ts
// 配置：chunk 名 + 匹配模式列表（顺序敏感——先匹配先返回）
const vendorChunks: Array<{ name: string; patterns: string[] }> = [
  { name: 'vendor-vue', patterns: ['/vue/', '/pinia/', '/@vue/'] },
  { name: 'vendor-ui',  patterns: ['/element-plus/', '/unplugin-vue-components/'] },
]

manualChunks(id) {
  if (!id.includes('node_modules')) return undefined  // 业务代码不归 vendor
  for (const { name, patterns } of vendorChunks) {
    if (patterns.some(p => id.includes(p))) return name
  }
  return 'vendor-utils'  // 其他所有第三方
}
```

**缓存效益**：

| 场景              | 缓存策略                                                       |
| ----------------- | -------------------------------------------------------------- |
| 首次访问          | 下载所有 chunk（vendor-vue + vendor-ui + vendor-utils + 业务） |
| 升级 vue          | 只 `vendor-vue` hash 变，其他 vendor 命中缓存                  |
| 升级 element-plus | 只 `vendor-ui` hash 变                                         |
| 业务代码改动      | 只业务 chunk hash 变，3 个 vendor 全部缓存命中                 |
| 纯开发不升级      | 全部 304 Not Modified（极快）                                  |

**手动验证 3 种方法**（详见 `docs/01-工具兼容性问题踩坑记录.md`）：

```bash
# 方法 1: 浏览器 DevTools Network 标签（最直观）
pnpm dev
# F12 → Network → 刷新 → 筛选 JS chunk

# 方法 2: sourcemap 验证（最准确）

for f in dist/assets/vendor-*.js.map; do
  cat "$f" | grep -oE 'node_modules/[^"]+' | sort -u
done

# 方法 3: 改源码对比 hash 变化（最直观感受缓存）

echo "--- 修改 src/App.vue 末尾加个空行 ---"
pnpm build 2>&1 | grep vendor  # 对比：业务 chunk 变 hash，vendor 不变
```

#### 包体积分析（rollup-plugin-visualizer）

**目的**：直观查看打包产物中各模块的体积占比，精准定位优化目标（如 `vendor-ui` 占了 477KB / 167KB gzip 太大时，可以排查是否引入了整个 `element-plus` 而不是按需引入）。

**配置**（vite.config.ts）：

```ts
import { visualizer } from 'rollup-plugin-visualizer'

// 在 plugins 数组里条件添加
...(process.env.ANALYZE === 'true'
  ? [
      visualizer({
        filename: 'dist/stats.html',
        gzipSize: true,        // 同时显示 gzip 压缩后大小
        brotliSize: true,      // 同时显示 brotli 压缩后大小
        template: 'treemap',    // 树状图（模块层级清晰）
      }),
    ]
  : []),
```

**为什么默认关闭（通过 `ANALYZE` env 变量启用）**：

- 视觉化生成耗时（build 时间 +200-500ms）
- 不想每次 build 都生成 `dist/stats.html`（仓库 diff 噪声）
- 想分析时手动启用

**package.json scripts**：

```json
"analyze": "ANALYZE=true pnpm build"
```

**使用方法**：

```bash
# 1. 跑分析（生成 dist/stats.html，~955 KB）
pnpm analyze

# 2. 浏览器打开
# Windows
start dist/stats.html
# macOS
open dist/stats.html
# Linux
xdg-open dist/stats.html
```

**生成的 `dist/stats.html` 含什么**：

| 维度           | 内容                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| **可视化样式** | 树状图（treemap），模块按层级嵌套                                             |
| **大小统计**   | 原始 / gzip / brotli 三种大小并列显示                                         |
| **模块分类**   | 按 `vendor-vue` / `vendor-ui` / `vendor-utils` 三大 vendor chunk 直观展示占比 |
| **依赖来源**   | 标出每个模块来自 `node_modules` 还是 `src/`                                   |
| **交互**       | 可点击进入子目录、悬停显示详细大小                                            |

**典型优化场景**：

| 现象                  | 优化方向                              |
| --------------------- | ------------------------------------- |
| `element-plus` 占大半 | 改用 unplugin-vue-components 按需引入 |
| `vue-i18n` 整个引入   | 改为按 locale 动态 import             |
| 业务 chunk 偏大       | 拆分子路由 / 动态 import              |
| `vendor-utils` 偏大   | 排查重复依赖（pnpm dedupe 检查）      |

## 📦 状态管理架构

按 spec §5 模块边界铁律：

```
全局 store/modules/        业务模块 store/
├── app.ts (侧边栏/语言)  ├── modules/auth/store/
└── user.ts (token/权限)   ├── modules/user/store/
                           └── modules/home/store/
```

**Pinia Setup Store 风格**（更接近 composables 心智）：

```ts
// src/store/modules/user.ts（2026-08-12 httpOnly 改造后实际形态，完整示例见 docs/19-Pinia store使用规范.md）
// 凭证由后端 Set-Cookie 写入 httpOnly cookie，前端不可读；
// 前端只持 sessionStorage 'auth' 标记供守卫同步判断
export const useUserStore = defineStore('user', () => {
  const authenticated = ref<boolean>(Session.get<boolean>('auth') ?? false)
  const profile = ref<UserProfile | null>(null)
  const permissions = ref<string[]>([])

  const isLoggedIn = computed(() => authenticated.value)

  async function login(credentials: LoginPayload) {
    /* 调 authApi.login + Session.set('auth', true) + fetchProfile + preloadDict */
  }
  async function fetchProfile() {
    /* 拉 profile + 填 permissions */
```

## 🐛 故障排查

### 1. `pnpm dev` 启动报 `IGNORED_BUILDS`

**症状**：`Ignored build scripts: @parcel/watcher, esbuild`

**解决**：`pnpm-workspace.yaml` 加 allowBuilds：

```yaml
allowBuilds:
  '@parcel/watcher': true
  esbuild: true
```

### 2. Vitest 报 `Unknown file extension ".css"`

**原因**：vitest 默认不处理 CSS 导入

**解决**：`vitest.config.ts` 加 `css: true` + `server.deps.inline: ['element-plus']`

### 3. Vue Router 报 `No match found for location`

**原因**：路由 path 配置错误或 404 fallback 未配置

**解决**：检查 `src/router/modules/*.ts` 的 path 配置，并在最后加 catch-all：

```ts
{ path: '/:pathMatch(.*)*', redirect: '/404' }
```

### 4. Pinia store 跨模块引用报错

**原因**：违反模块边界铁律（modules 间不互相 import 内部）

**解决**：模块间通信通过 `modules/<m>/index.ts` 暴露的对外接口

### 5. `vue-tsc --build` 报 "Cannot find type definition file"

**解决**：检查 `tsconfig.app.json` 的 `types` 字段是否包含 `vite/client` 和 `node`
